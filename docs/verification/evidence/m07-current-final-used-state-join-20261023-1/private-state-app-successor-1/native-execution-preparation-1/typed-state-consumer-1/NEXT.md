# Typed state-app consumer implementation

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

Private native_diagnostic.py adds one fixed-app typed stdout branch. The original f4c3 runner, exact-byte oracles, futex stderr oracle, collector and lifecycle/ownership guards remain preserved. The standalone helper is included byte-for-byte in the runner; tests import the actual runner implementation. Eighteen modeled TESTONLY fixtures are written and have NOT run. See SOURCE-AND-FIXTURE-PROPOSAL.json for exact command/profile request and source hashes.

The parser derives eligibility from actual reported feature/layout rows, then requires exact ordered per-boundary/per-component source-bound attestation and original-restore outcomes. It cannot directly inspect physical registers. Complete0 can yield diagnostic PROTOCOL_PASS; partial77 yields PROTOCOL_PARTIAL and preservation_pass=false; app1/signals/malformed output fail. No app or native acceptance flags are promoted.

No ordinary CPU job is started without the requested grant. Before actual staging, bind the existing one-app M07 collector/PAIR_CPU environment and waiter-thread lifecycle profile coherently. The preserved generic runner still freezes PATH/COKERNEL_PATH environment and a single-thread trace shape, so a typed stdout branch alone is not a runnable guest packet. No guard has been removed to hide that constraint. Whole M07 remains open; old mask7 evidence, frozen LONG and separate M14 remain untouched.
