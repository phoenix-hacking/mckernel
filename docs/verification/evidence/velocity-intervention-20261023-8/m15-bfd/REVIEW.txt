Exact ABI/layout argument and executable witness

The original functions return BFD macros. Under the supported non-DEBUG_BFD_SEND
header, each macro evaluates the target callback at abfd->xvec and calls it with
the original bfd pointer and, for canonicalize, original asymbol**. There is no
project behavior between the macro call and returning its long value.

Nonshipped cmake/bfd_layout_witness.c includes the pinned absolute Rocky header,
asserts x86_64 Linux, 8-bit bytes, LP64 and 8-byte pointer/function-pointer
size/alignment, checks callback types using C11 _Generic, and checks the three
field offsets are aligned. Its executed output supplies only offsetof(bfd,xvec),
offsetof(bfd_target,_bfd_get_symtab_upper_bound), and the canonicalize offset to
Rust. It also reports exact bfd/bfd_target sizes/alignment. The job retains the
full preprocessed witness and requires the two macro expansions to be precisely
the ordinary target dispatch expressions, rejecting DEBUG_BFD_SEND or an
unexpected macro implementation. No constants are guessed or checked in here.
CMake pins header/library/compiler, rejects cross compilation and DEBUG_BFD_SEND,
and regenerates the native witness on configure. It adds header/library configure
dependencies and the generated Rust constants as object dependencies. Native
qualification separately pins the mounted nightly Rust executable. The witness
is configure/test orchestration: its C code is never linked into delivered tools.

Rust uses raw pointer reads at those checked field offsets. It forms no Rust
reference to BFD storage and gives BFD no Rust-owned allocation. Extern C callback
arguments and c_long returns match LP64 bfd*/asymbol**/long; caller declarations
using isize are the same 64-bit ABI. No BFD object is copied. All four symbols
refer directly to the selected third-party BFD callback, with no call to an old
project wrapper. The original valid-BFD/live-xvec/non-null-callback preconditions
remain. Null BFD, dead target and invalid buffers remain outside both contracts.

Behavior, errors and ownership

Neither wrapper family allocates, retains, frees, closes, locks, logs or modifies
BFD state beyond whatever the selected third-party callback does. Negative,
zero and positive long values pass through; error state and errno pass through.
The canonicalization callback receives the exact same pointer-to-pointer storage.
Its symbol ownership remains BFD's, and caller storage remains the caller's.
The borrowed BFD and target must outlive the callback, and returned symbols must
remain within their existing BFD lifetime. No source-lifetime extension is added.

Existing tool initialization behavior is intentionally reused byte for byte:
open/format failures and negative adapter results report existing BFD errors;
zero upper bounds print existing no-symbol diagnostics; allocations and global
symbfd/symtab/nsyms assignments retain their original ordering. Existing early
error resource-retention behavior remains as-is. This lane neither invents new
cleanup behavior nor claims to resolve existing full-tool lifetime debt.
