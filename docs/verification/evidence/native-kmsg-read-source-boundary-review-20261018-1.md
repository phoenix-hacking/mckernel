## Findings

1. **Existing consumer and routing:** `OsDeviceFamily::register` installs this production `OS_FOPS`; native and compat ioctl callbacks both enter `os_request`. The new existing public command `IHK_OS_READ_KMSG=0x112a20` branch follows exact-generation file/object resolution and `operations.lock()`, precedes the NotBooted/backend gate, and does not overlap the application-service command set. Thus Ready/Failed/Shutdown logging does not require creating an application service or reopening admission. It uses the allocation owned by that live `OsObject`, not an arbitrary physical/user address. The branch is ordinary production routing, not a test-only consumer. Real module selection/linking remains a target-build observation.

2. **ABI and byte semantics:** `repr(C)` ring size is 4 MiB, with 32-bit lock/tail/length/head at offsets 0/4/8/12 and data at 4096; data capacity is 4,190,208 bytes. Required fixed length and nonnegative in-range head/tail are checked before data access. For head <= tail, raw `tail-head` bytes preserve embedded NULs. For head > tail, bounded bottom `strnlen` followed by raw top bytes exactly preserves the legacy asymmetry. The wrapped total is strictly below data capacity because tail < head. Equal head/tail is empty. Snapshot does not shift head/tail or add a terminator. Pointer spans and independent output allocation are sufficient and nonoverlapping, including zero spans.

3. **Shared lock and unsafe premise:** the guest producer in retained `debug.c` uses the same aligned 32-bit CAS(0,1) word and zero unlock. Host Acquire CAS and Release zero publication are appropriate for the supported coherent x86_64 shared ordinary-RAM protocol. Raw metadata accesses and bounded copies occur only after acquisition, with no Rust reference to the concurrently mutable whole ring/data. The only shared Rust reference is to the atomic lock word. The guard releases on success and invalid-metadata returns; an unsuccessful acquisition never clears a guest-owned lock. This is hardware/FFI synchronization with the accepted C guest producer, not a portable Rust/C abstract-machine proof. Keep the supported x86_64 coherent mapping and producer ordering premises when binding the native artifact; this patch changes neither producer nor mapping.

4. **IRQ and progress:** in this native ownership path the buffer is newly privately allocated and exposed to the backend only as the guest boot physical buffer. The reviewed native source paths contain no Linux IRQ reader/writer of that ring and do not register it in the legacy C host ring-container list. Therefore omitting Linux local IRQ masking does not introduce a same-host-CPU lock-recursion participant. Guest interrupt exclusion remains the producer's responsibility. At most 65,536 failed acquisitions return EBUSY; this deliberate bounded behavior differs from legacy infinite spin and is acceptable for a diagnostic read of a failed/stopped guest. It can also report transient contention; callers must not interpret EBUSY as an empty log. Snapshot work is finite, allocation-free and non-sleeping while holding the ring lock. Scheduling/preemption means no absolute wall-clock bound is established.

5. **Allocation, copy and callbacks:** the full initialized private output is allocated before the shared lock. Allocation failure propagates ENOMEM. UserSlice checks/copies the supplied native or zero-extended compat user address after the ring guard and atomic reference have ended; failed/partial usercopy returns legacy EINVAL and leaves the ring unchanged. No raw user dereference or retained user pointer exists. The OS operation mutex remains held across allocation/usercopy, which can sleep, so this is a process-context ioctl and not a strict-duration operation. No application/provider callback is invoked by this branch, and no guest-ring lock/reference crosses usercopy. Existing foreign-callback lock/lifetime contracts are unchanged.

6. **Generation/lifetime:** the Linux file reference retains its immutable `OsLease` throughout the callback. The registry lease excludes destruction/minor reuse, and the operation mutex serializes boot/shutdown/backend release with the read. Destroy obtains exclusive registry ownership before removing/dropping the exact object; it cannot free this allocation during snapshot or copyout. Existing shutdown/failed-boot retirement obligations still govern when guest access actually ends. The new reader neither frees/reinitializes the ring nor bypasses those obligations. Fresh object allocation gives a fresh zeroed ring on generation reuse.
