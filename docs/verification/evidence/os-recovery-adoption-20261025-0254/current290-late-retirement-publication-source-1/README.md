# Finite late retirement publication helpers

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

These two source-only helpers remove inline grant construction from the120-second live standby interval. They preserve the existing epochs, standby duration, fixed2026-10-27T11:24:50Z wall deadline and exact earlier monotonic/BOOTTIME ends. They do not alter account, budget, watcher or runtime controls. They perform no process observation, runtime launch, signal, retirement, wait, polling or automatic retry. File I/O completes finite bounded metadata operations only.

1. After a fresh reviewed standby launch under preparation2 or a later fresh successor preparation, UID1000 invokes `prepare_retirement_grant.py PREP`. It reads only the exact LAUNCH-PACKET.json, RUNTIME/PROCESS.json and RUNTIME/HELD-CUSTODY.json metadata (plus directory identities), enforces the exact existing selected sources/target/new actual keeper/launch binding and writes an exclusive ROOT-ACTUAL-PREDECESSOR-RETIREMENT-GRANT.json. It prints the grant reference and keeper identity. This prepared grant is not publication or execution authority.
2. Obtain the actual independent custody_release_review PASS of that exact new grant SHA. Expired preparation1, keeper1203549 and earlier grants cannot be reused.
3. Root invokes `publish_reviewed_retirement.py PREP APPROVED_GRANT_SHA` only after that actual PASS. It requires UID0, rederives the complete expected grant from unchanged current metadata and requires the exact explicitly approved SHA. It writes a new Root-authored record of the independent review, including Root's explicit CLI approval attestation, then exclusively creates INBOX/command-000000.json for RETIRE_EXACT_PREDECESSOR_KEEPER_PIDFD_ONLY. The helper never performs or invents a review; Root's actual prior review confirmation is the required invocation precondition. It pins the sibling preparation helper source and works under isolated Python -I.

Existing outputs are refused before publication; both writes also use O_EXCL and O_NOFOLLOW. A write failure may leave a partial publication for reconciliation; the helpers neither remove it nor retry. Parent directories must be real canonical directories without symlink components, and the actual inbox directory must match the launch's exact root-owned0700 identity. Source/metadata references retain their actual byte lengths and hashes.

Ten private metadata fixtures pass on CPU0 with a2GiB address-space limit. Root inbox ownership is simulated only inside private fixtures, never changed on the host. Fixtures verify correct exact publication, unchanged input bytes, invalid hash, changed grant/source, no overwrite, expired keeper, symlink parent and UID refusals, plus isolated-interpreter dependency loading. FIXTURES.stdout, FIXTURES.stderr and FIXTURES-RESULT.json retain actual output, command, exit0 and source hashes. No actual Root inbox, production process, privileged operation or native workload was used by those fixtures.
