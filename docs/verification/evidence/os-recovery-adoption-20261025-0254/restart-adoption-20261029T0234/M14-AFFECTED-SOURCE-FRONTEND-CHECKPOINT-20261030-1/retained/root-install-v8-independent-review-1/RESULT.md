**NO-GO for operation-only retirement on three concrete completion/custody issues.**

1. `install_issuer.py` calls `retire_lease_if_authorized` and closes the lease before returning; `BOOTSTRAP-CODE.py` then writes the only full result to stdout. If the write is short or fails, it latches UNKNOWN after the same lease OFD has been closed and cannot restore that custody; the preceding journal completion event contains only nonce/closure/native flags, not the complete terminal/census/23-file/capture evidence. Durably publish the complete nonce/source/identity-bound result to the actual owner before any authorized lease close, keep the lease on failure, and record the final close disposition separately. A post-close publication failure must not claim lease retention or retry a possibly closed FD.

2. `install_completion.py:29–62` scans proc nonatomically. It collects birth values but does not compare them to stable pre/post identities, terminates ancestry traversal when a parent is absent from rows, and only binds proc inode plus the observer's PID namespace, not complete process visibility. Ordinary exit/reparenting/PID reuse can change the ancestry while enumerating; repeated scans do not prove continuous empty group or no surviving escaped descendant, and proc mount visibility can omit processes without an enumeration error. Therefore its `private_group_empty=True` / `keeper_descendants_empty=True` booleans are not by themselves proof needed for automatic lease close. Use actual independently admitted exclusive containment/child-creation custody and a bounded stable proof or retain UNKNOWN. No hostile root or security scenario is assumed; no native clearance follows.

3. Issuer stamps `timer_started_boot` immediately before guarded fork, earlier than actual GNU timeout execution. The final revision's `remaining_timeout_budget` subtracts that pre-exec interval from 65 seconds, so it can underestimate the timer's real remaining TERM/KILL interval and consume the advertised issuer join/capture reserve. The >=60-second pre-GO rejection is conservative, but does not fix this upper-bound error. Derive the conservative timer-start upper bound from an authenticated READY timestamp after timeout has begun, or reserve the full 65 seconds plus positive join/capture at GO. Preserve min(BOOT, MONO, UTC) caps and classify failed timing/joins UNKNOWN.
