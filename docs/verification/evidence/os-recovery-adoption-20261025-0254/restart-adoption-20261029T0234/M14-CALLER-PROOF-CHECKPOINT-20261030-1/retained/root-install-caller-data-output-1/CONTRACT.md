# Root install DATA output: source and patch proposal

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. Source only, unreviewed and untested. The proposal applies to exact parent source `root-install-parent-successor-2/root_parent.py` SHA-256 `7d97d9f905f50e0cb4308411a1786d37361356afd2e104b2b1fc063cd854f74d`; SDK owns actual parent/bootstrap composition. No command, authority, root identity or native current-free is created by these records.

`data_output.publish_full(nonce, profile_sha256, verified_result, caps)` validates actual parent PID and process birth by reading `/proc/self/stat`, strict nonce/profile and complete actual keeper/installer terminal evidence, the parent-verified proof and held lease status. It writes exactly one compact sorted JSON line with record type `ROOT_INSTALL_FULL_DATA_V1`, scope `ROOT_CODE_INSTALL_ONLY`, nonce, profile SHA, actual `root_parent` PID/birth, native release false, native current-free null, and the complete already independently verified result. The SHA-256 return value covers the exact newline-terminated bytes. The output is DATA, not authority. The parent must independently verify proof and Root authority before invoking it.

`data_output.publish_disposition(nonce, profile_sha256, full_sha256, lease_disposition, outcome, caps)` emits exactly one `ROOT_INSTALL_DISPOSITION_DATA_V1` JSON line, binding the same nonce, profile, actual Root PID/birth and FULL SHA. Accepted pairs are `HELD/UNKNOWN`, `CLOSURE_UNKNOWN/UNKNOWN`, `VERIFIED_CLOSED/UNKNOWN`, and `VERIFIED_CLOSED/COMPLETE`; all records preserve native release false and native current-free null. The helper never closes an operation FD and requires an actual prior successful FULL by the same parent. Failure is sticky and output is never retried.

Both writes use the existing actual fd 1, which the admitted Root caller must provide as an exclusive, writable, single-link regular capture file. The helper checks current cap values and stdout identity, bounded record size at most 2 MiB, a single exact byte-count write and `fsync`, then rechecks the caps and actual parent identity. It bypasses buffered Python stdout: no separate buffered flush is claimed. The existing parent deadline watchdog must remain active during writing and fsync. An I/O error, short write, fsync failure or expired cap is UNKNOWN. The caller's owner must retain any partial capture and never equate DATA with an independent release.

The private `parent-data.patch` is a reviewable proposal: parent `run` carries actual keeper direct wait and installer pidfd/direct-wait evidence, `serve` first fsyncs its complete proof journal, then publishes FULL and obtains its digest, and only then checks conditional authority and attempts the exact single owned lease close. A false retirement request publishes `HELD/UNKNOWN` and retains the live owner. After a successful close and journal, it emits `VERIFIED_CLOSED/COMPLETE`; on later failures it retains the actual close state and can emit a single UNKNOWN disposition when that output has not already been attempted. The SDK bootstrap must load the helper by reviewed exact source hash, provide actual profile/receipt inputs and avoid its previous extra summary write. This patch does not mutate the SDK parent or grant an operation.

`test_data_output.py` prepares mocked exact wire, short-write, fsync, post-close failure, cap and type cases; `test_parent_data_order.py` exercises the actual private parent proposal with mocked handles to check FULL failure precedes any close and post-close journal failure reports VERIFIED_CLOSED/UNKNOWN without retry. These test sources have not run. Independent source review, a separately admitted bounded light test and actual operation admission remain required.
