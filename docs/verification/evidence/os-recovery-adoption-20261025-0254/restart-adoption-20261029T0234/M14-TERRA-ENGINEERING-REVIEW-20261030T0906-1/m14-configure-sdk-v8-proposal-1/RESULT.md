## Reuse boundary and required successor

The existing v8 owner is a suitable lifecycle starting point, but its current code cannot express this operation merely by substituting the new mounts or argv:

* `sdk13_data32_input_validation.py` lines 113–129 requires exactly 30 mounts, exact e6a profile and four matching archived compiler commands; `_collect` binds those to the old proposal/source-map and derives outputs from the four commands. Composite ON overlays and configure stage violate this contract.
* `sdk13_four_command_driver.v4.py` lines 16–48 pins e6a, exactly four named stages and `/work/output/build/kernel`; its effective-view check also pins the old proposal and source-map. This is neither a configure driver nor a post-generation validator.
* `sdk13_compile_image_owner.v8.py` lines 1943–1965 and 2186–2255 bind the old profile, driver, work/evidence domain, command, operation and root documents. Lines 2319–2354 demand four compiler exits and object/link depfiles. Reusing those result checks would misreport configure-only behavior. Its namespace, consumed nonce and evidence path must not be reused.

A minimal source successor should retain the reviewed v8 lease, mount identity/effective-view, direct process/capture, signed deadline, exact-CID containment and retirement mechanisms, while creating a separate unique operation/profile/nonce/work/evidence domain. Bind a successor exact ON mount list and complete source-map to the retained overlays and verifiers; update the existing validator and snapshot checks for their exact membership, source quiescence and nonintersection. Replace the fixed four-stage driver with a source-bound configure stage and separate post-generation verification stage with explicit argv/cwd, independent wait/status/streams, timeout and output requirements; fail closed on any missing or ambiguous status. Adjust owner result evaluation to require those new receipts and the configure artifacts rather than four object/link outputs. Bind new owner, helper, driver, validator, profile and source map digests and independently review their coupled diff and negative/timeout tests. Preserve v8 and earlier failure evidence. This is a necessary patch specification, not an implemented or reviewed patch; do not relax v8's admission facts or infer that its previous operation release covers this successor.

The old v8 profile's CPU6/1 CPU/4 GiB/no-swap/128-pid limits and up-to-2500-second request bound are historical constraints, not current availability. BTF is enabled in the observed kernel config and may read the 345,265,952-byte vmlinux and invoke `pahole`/`resolve_btfids`; bind actual binary identities, configuration and workload cost, measured resource headroom and suitable timeout before admission. External watchdog must cover blocking Popen, reads, fsync and clock changes/suspend with exact UTC/BOOT/MONO deadlines and finite join/containment bounds. Track live process, client, cgroup, daemon and exact container identities; an exited client or stopped container alone is not retirement. Unknown effects or failed collection retain custody and leases. The actual guardian and monitor remain solely externally owned, and no physical run can be authorized by this proposal.
