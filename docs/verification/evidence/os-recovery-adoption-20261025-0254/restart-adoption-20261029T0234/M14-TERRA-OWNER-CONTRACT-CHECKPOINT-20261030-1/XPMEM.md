A new permanently live owner plus short IRQ-safe state locking could in principle protect publication, prevent two initializers from installing different generations, and issue active-operation reservations without holding the lock across host forwarding. It must distinguish a live generation from one being retired and count open/clone descriptor edges separately from temporary operations. That conceptual shape is not itself a selected implementation, a proved lock ordering, or evidence of correct reclamation.

The first source-level caller boundary is descriptor acquisition. `syscall_mckfd_find_locked` returns the raw list node after unlocking (`syscall_policy.rs:3496-3518`); `syscall_ioctl_body_result` then reads and calls its callback (`:3558-3604`). A concurrent close detaches the same descriptor under the lock, then invokes its close callback and frees the descriptor outside it (`:3625-3687`). The actual XPMEM ioctl body passes this same descriptor through ATTACH after usercopy (`xpmem_helpers.rs:3529-3707`); `xpmem_attach_body_result` reads its fd much later before calling the mapping provider (`:7208-7462`). Acquiring a partition reservation at entry to XPMEM ioctl cannot retroactively pin the descriptor or prevent an already closed/reused host fd; holding the process spinlock over usercopy and mapping is not a valid substitute. A safe selected implementation therefore requires a real descriptor acquire under the list lock, callback-held release on all success/error/TOFU paths, and a close finalizer that preserves the descriptor and its XPMEM owner until the callback retires.

That finalizer cannot simply defer the original close callback to an arbitrary last reader or wait under the existing lock. Close currently invokes callbacks in the closing context and then forwards host close; the VM release path calls all close callbacks while holding `mckfd_lock` (`process_helpers.rs:11525-11538`). The actual callback can flush and destroy XPMEM TG state before partition exit. An owner must specify exactly who drains users, when callbacks/host close run, and how VM teardown avoids waiting under the process lock. Existing waitq prepare/wakeup take a noirq lock (`waitq.rs:300-318,360-381`); the actual IRQ/reentrancy and no-lost-wakeup contract for a last-user finalizer is not bound. Returning a new busy error or silently delaying/omitting close would change behavior.

Open/clone/failure edges are also required: open forwards the host request and creates a TG before publishing its descriptor and increments `n_opened` only after list unlock (`xpmem_helpers.rs:3371-3515`); fork copies descriptors under the child lock, invokes XPMEM dup, ignores its result, and on later failure frees copied descriptors without the matching close (`process_helpers.rs:13908-13940,14026-14031`). The TG helper exposes no created-versus-shared owner token, and a successful host open has no source-bound rollback adapter/disposition for an uncertain close result. One cannot infer host FD closure, safely retry a potentially reused integer, or free a shared TG from those results. See `../m14-xpmem-tg-host-abi-blocker-1/RESULT.md` for the bounded host and TG evidence.

Minimum implementable next boundary: first bind a coordinated XPMEM descriptor pin plus synchronous/teardown finalizer contract with explicit owner and lock order; then a global partition-generation owner can acquire/release reservations at the actual open, descriptor callback, dup, close and teardown sites. It must keep source/C ABI compatibility or carry paired exact witnesses, cover fork rollback and uncertain host disposition, and remain unselected until independent ownership/concurrency review and applicable tests. This document identifies missing interfaces, not a working owner or an observed race.
