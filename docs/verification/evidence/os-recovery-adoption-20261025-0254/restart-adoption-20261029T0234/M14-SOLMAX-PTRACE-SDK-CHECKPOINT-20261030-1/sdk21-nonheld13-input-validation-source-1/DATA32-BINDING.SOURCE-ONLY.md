# SDK13 data32 input binding successors

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.
These are private source-only successors. Neither source preparation nor a
passing future fixture would authorize a container, prove live input identity,
qualify SDK output or establish ABI/default/native acceptance.

`SDK13-DATA32-ADMISSION.SOURCE-ONLY.json` binds final profile e6a8462b and its
four exact commands, one fresh work target and 29 ordered read-only profile
mounts. It carries forward the source-only predecessor's 15 actual fact slots,
resource limits, retired-Root70 history, exclusions and null authority. The
new profile review is explicitly null. The proposal does not assert any fact,
current-free state, new nonce or current release.

`sdk13_data32_input_validation.py` is the c7df successor and has the same API:
`validate`, `bind_work`, `revalidate`. It pins final profile and proposal,
requires 157 Rust-tree regular files, checks every source-map Rust overlay hash
including `lib.rs` 9be57bde and `f06_debug_constants.rs` e24e8adf, and checks
architecture C mount b2db4dce via the exact final profile. It additionally
requires both the Rust `f06_debug_constants_candidate` and C
`MCKERNEL_RUST_F06_DEBUG_CONSTANTS` selector. Earlier 13 function selectors,
8 retained objects, toolchain and lock, inputs, all mount order/ancestry,
identity and source checks remain carried over. A final reviewed source map,
root release and live checks are required; c7df's old source map or proposal
must not be treated as final-data32 authority.

`sdk13_data32_input_snapshot.py` is the 8268 per-attempt successor with the
same `begin_snapshot`, `bind_work`, and `revalidate` API. It authenticates the
new validator; profile/proposal, request, source-map, owner, lease and live
admission context are inherited through that module and guard. Old snapshot
objects or tokens have no valid binding for this successor. As documented in
`SNAPSHOT-API.SOURCE-ONLY.md`, a genuinely reviewed initial byte/identity
association, complete file/directory/symlink metadata checks and current
quiescence are mandatory. This source does not inspect Docker or query physical
custody. A separate fresh release and independent owner/lifecycle review are
still necessary, including the prelease sequencing and actual source
quiescence identified by the compositor. Effective mounted input bytes must
still be checked inside the reviewed driver before compiler entry.

The base6153 JSONL 2c9eac14 and nightly ledger eeabd12d retain their historical
point-in-time scope, unchanged. The final Rust root is a copied tree; the prior
156-file ledger cannot supply its inode identities. Its 157-file HOST163 closure
supplies source paths and hashes but not joined hash+identity observations.
A fresh, independently reviewed, exact final Rust-tree byte/identity receipt,
normalized ledger converter and per-attempt quiescence binding remain required.
The data32 source-map draft 4172db42 is source only, not that receipt. No value,
review, live image/tool proof or current resource authorization is invented.

The paired unrun fixture sources check selected data32 flags, rejection of old
profile/proposal, retained existing selectors and mount/tree behavior, and
snapshot invalidation for changed content/metadata, root/profile, lease,
admission, directory masks and symlinks. They are not real producer checks.
