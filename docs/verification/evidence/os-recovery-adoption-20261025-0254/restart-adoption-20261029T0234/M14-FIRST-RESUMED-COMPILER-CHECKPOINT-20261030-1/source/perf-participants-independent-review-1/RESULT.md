**Concrete corrections before production composition:**

1. `perf_descriptor_participants.rs:260–267` treats all `registration_key_locked` errors as `Ok(false)`. Owner `perf_group_owner.rs:221–230` converts a registry search error and mismatched opt/active state to the same `-EINVAL` as no entry. If a future caller treats false as permission for legacy close, it can free a descriptor/event while registry ownership remains. Expose distinct absent / found / invariant-or-search-failed results. Return false only for a positively identified nonparticipant; stop and preserve the descriptor/registry on lookup or participant mismatch. In particular, an expected perf callback with absent registration must not silently enter legacy free.
2. `register_descriptor_locked` checks read/ioctl/mmap/close/fcntl, opt and data but never checks `dup_cb`; `clone_registered` rejects non-NULL and current legacy fork may call it. Enforce null before registration unless a separately implemented valid callback contract is supplied. Record the rejected lease and inputs as currently done.
3. Publication and child clone do not test fd uniqueness. A genuinely fresh unique process-local fd and empty/nonconflicting destination list are unsafe caller preconditions, not established by the module. Check under the same process lock before list insertion (unwind/retain exactly as registration failure), or bind and prove those guarantees at the actual callers. `parent == child` is not rejected, so an ordinary same-fd clone into the same list is a concrete example requiring rejection or supported semantics.
4. Owner `allocate_registration` casts tracked memory and performs `ptr::write` without checking alignment, unlike participant record and sidecar paths. Apply a pre-write `align_of::<Registration>()` check and matched free on failure or provide the exact tracked allocator alignment contract. All methods remain unsafe and depend on unique, live, initialized, nonaliasing process, descriptor, registration and event inputs; annotations alone do not enforce these obligations.

**What is implemented, conditionally:** acquisition holds process → registry → group locks and pins both event and group from an active registry entry before returning `OpenGroup`. A root pin carries a separately allocated outcome record; release either frees the unused record for an empty batch or retains final/quarantine output. Member fd is exposed distinctly and intentionally rejected for publish. Root publication tests `leader_closed`, holds the process lock over member link, registry insertion and list insertion, and a registration failure unwinds the published lease into a retained detach/quarantine outcome. Standalone initialization creates event and group sidecars, transfers pending ownership on abort or failure to a record, and publishes registration/list under one process lock. Clone validates parent list membership and generation under parent → registry → group lock, increments the descriptor pair, then snapshots the descriptor under the parent lock and attempts child registration under the child lock. Failure transfers both descriptor/registration and the exact unwind outcome or unconsumed lease into a record. Close unregisters under the lock before list unlink, then returns descriptor and typed detach outcome to a record. No double free is apparent in those transitions under the stated allocator, lock and input custody premises; the code deliberately does not free final batches.

Record storage is preallocated through the tracked kmalloc bridge, alignment checked and written before operations; only vacant records are freed through its paired tracked-free bridge. Nonempty payloads are retained in an IRQ-spinlock-protected append-only list after process locks are dropped. This retains ownership but has no consumer, recovery, bound, or teardown. It leaks/exhausts memory and cannot be selected as a complete runtime owner. The precise actual allocation/free implementation, IRQ/reentrancy and lock order require source and runtime proof, and all paths must actually consume reservations exactly once. `must_use` cannot enforce the unsafe protocol.
