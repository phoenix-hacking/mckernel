# Focused adapter close-state review

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. Source-only review; no tests, actual fork, pidfd/signal operation, install or workload. Full filesystem access / approval never retained; other writers and predecessor evidence preserved. No physical release follows.

**NO-GO for source integration.** The correction removes eager disposal on adapter constructor/revalidation errors, enters `CLOSING` and publishes before socket/pidfd close, and records `VERIFIED_CLOSED` with `fd=None` after the close returns. Interruption/partial close produces `CLOSURE_UNKNOWN` with a historical number marked possibly closed and no retry; this is materially better than claiming a possibly closed descriptor is live. Configured stop deferral covers the guarded close under the code's limited asynchronous-signal assumptions. Journal failure remains UNKNOWN and external process/watchdog retirement is separate.

1. `adapter.py:close` checks `owner.state` under `session_lock`, but `compositor.py:retain_session_unknown` acquires neither that lock nor an owner state lock. A close can pass the owner check, enter `CLOSING` under record lock, and then a concurrent UNKNOWN transition sets owner state and sees the record already CLOSING, so skips `record.retain_unknown`; the close proceeds after owner UNKNOWN. Serialize owner UNKNOWN and close admission/disposition under one shared ordered lock/state machine and define reentrant behavior; if UNKNOWN wins, it prevents close, while a close already in progress must retain its precise in-progress/partial disposition, with no false live-FD claim or resurrection. Test deterministic interleavings without real descriptors. This is a concrete new blocker, also identified by the source owner.

2. `adapter.py` initializes `self.sock=None` then evaluates `socket.socket(fileno=os.dup(fd))` outside configured-stop deferral. A raising configured stop after successful dup but before the integer is assigned to a registered owner/session can strand an untracked open descriptor. Preallocating the session does not retain an integer that has not been attached. Cover dup-to-owner/session handoff with the same bounded configured-stop discipline and record partial constructor outcomes; other uncatchable/injected exceptions require external process custody. Test the exact boundary with mocked acquisition and stop.

3. `validator_consumer.consume` now returns a typed bytes-only wrapper derived from `_collect` after existing source/effective/collector checks, removing the prior blanket post-collector refusal. However, `validator_entry._consume_prepared` stores that wrapper only in a local variable, then returns None; `run()` and `VALIDATOR_INLINE` also discard it. Successful collection would not deliver data to any consumer. Provide a concrete result return or existing owner/protocol handoff after confirmed disposal, and preserve UNKNOWN on failed disposition. No new approval marker is warranted. The three original gates, profile and pins remain held.

Prepared `test_actual_close.py` has six synthetic tests, mocks close/socket/pidfd capability and signal-mask/delivery APIs, and exercises the actual session close plus constructor/revalidation failure methods, but lacks the owner-vs-close concurrent interleaving and dup handoff tests. `test_validator_consumer.py` is also fake-data-only; predecessor callback fixture has six mocked tests and is to run in its own interpreter. The focused fixtures are reasonable candidates for a separately admitted CPU6 / 512 MiB light profile, with exact module/interpreter hashes, capture, output isolation, resource limits and retirement. This source-only review did not execute them; tests do not prove real syscall outcomes or root/physical custody.
