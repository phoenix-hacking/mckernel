# M14 perf group-failure actual-body local regression

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. Local host mocks only; no actual perf syscall, IKC, configure, Kbuild, Docker, native kernel, guest, privilege, controller or cleanup occurred.

This tests an uncovered source-reviewed lifetime branch of the retained nonheld13 `sys_perf_event_open` candidate. The Rust harness directly imports the unchanged genuine `f03_perf_group_cleanup.rs` module (SHA256 `0dc2c777c39a9b2f31bc5e3d80badd2d3de8db35bcd0adba205776bb58517293`), calling its `perf_entry_with_group_cleanup`; its actual validation, counter and group helpers are byte-extracted from the selected Rust policy. An independently compiled C object contains the actual original C `perf_event_open_group_body_result` and bit helper, with only the group symbol renamed to avoid collision. `INPUTS.json` binds actual sources. CPU/thread/event/FD memory layouts in the harness are explicit synthetic mocks; event allocation, counter scan, tracked free and attribute copy are mocks. The full `sys_perf_event_open` entry and actual runtime provider bindings are not executed.

Three invalid-group cases passed: missing FD, matching FD with null event data, and matching leader whose sibling predecessor is null. The C and Rust actual group helpers both returned `-EINVAL`; the selected Rust entry returned the same error and called its free mock exactly once with the fresh event pointer, before any host syscall or later FD allocation. Leader sibling pointers, count and status remained unchanged; the malformed-list case permitted the private event's leader pointer write before free, matching C helper behavior. The Rust cleanup is an intentional difference from the C fallback body, which returns the group error without that added free; no claim of full C lifetime equivalence is made. The free mock does not release real memory, prove absence of aliases, or establish actual provider/concurrency/lock lifetime.

Exact C and Rust build/runtime argv, output hashes and exits are in `RUN.json`; the final Rust and mock-run commands exited 0 with CPU0, 2 GiB address-space, 30 CPU-second, 8 MiB file and 45-second wall ceilings. The successful C object was reused from `../m14-perf-group-actual-body-correction-1/c_actual.o`, SHA256 `afc5d20aa676c48cfce2c2d39a4df14e5d071b1b5ec2f2e2b61e7f992f718cfc`, rather than recompiled. Final output SHA256 `00b3b48db9ee519335913d3dc3f67bb7b378270c9692a34343f7aaa270decb15` covers the three cases.
