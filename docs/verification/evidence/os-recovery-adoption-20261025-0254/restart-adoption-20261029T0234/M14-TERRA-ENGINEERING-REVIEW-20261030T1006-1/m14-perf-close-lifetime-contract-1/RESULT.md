# M14 perf close/group repair: source-bound lifetime contract blocked

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. Private source analysis only. No compiler, fixture, actual process observer, perf syscall, configure, Kbuild, Docker, native kernel, guest, privilege, controller or cleanup operation ran. No canonical source or other owner's files changed. No source repair is selected or claimed.

The existing group helper links a newly allocated member into the leader's intrusive list and increments its count before host syscall and FD publication. The selected `sys_close` unlinks an FD under `proc.mckfd_lock`, unlocks, invokes `f03_perf_close_v1`, whose `perf_close_body_result` clears the **closing current thread's** maps and calls tracked free on the event without unlinking its group entry; the descriptor is then freed. `perf_start`, reset, stop and group read follow raw `group_leader`/sibling pointers. The `FullMcPerfEvent` layout has those raw links and `nr_siblings`, but no explicit lifetime reference count or closed marker. These are source facts, not proof that a particular real execution reached a stale pointer.

A member-first close can leave the leader linked to the retired member; a leader-first close can leave remaining members pointing to the retired leader. Concurrent open/close can also overlap unlocked FD lookup with unlink/free. The FD lookup helper releases `mckfd_lock` before read/ioctl/mmap callbacks, so guarding only group insertion does not protect an in-flight callback. The opening thread's counter map is scanned and later updated, while close clears the closing thread's map; exact cross-thread ownership is unresolved. Host open may block, so an IRQ-saving spinlock must not be held across it. Subsequent host-FD/allocation failure rollback and group reservation are owned by the separate transactional-entry worker; these paths must use one coherent close/lifetime protocol.

A safe repair needs an independently established event/FD/leader pinning and last-owner reclamation rule, explicit lifecycle state for open-in-flight, descriptor-open and closing, a lock/order that covers all group readers/writers and close while permitting waits outside the spinlock, counter-map owner lifetime and uniqueness, and a decided leader-first semantic (retained leader until last member or a fully specified promotion/detach contract). A member unlink must maintain both links, sibling count and appropriate status/counter bookkeeping while every reader is pinned; a leader must not be freed until all members, in-flight opens and readers relinquish the relevant pins. Last-owner close must consume each allocation exactly once. A test or mock cannot invent those ownership facts, and the original C behavior is not a concurrency oracle. The current event layout cannot encode the proposed state without an approved representation/provider change; adding a raw pointer registry or silently relying on `nr_siblings` alone would not establish it. Therefore no executable Rust patch is offered as safe under the available contract.

Future focused tests, after the protocol is implemented and a genuinely reviewed applicable light profile is available, should use actual group/open/close bodies with pinned synthetic providers: member close then append (list and count consistent, one free); leader-first close with live members (selected policy and last-owner free); simultaneous open/close with an in-flight pin and no lock across offload; later host/FD failures with transaction rollback; and cross-thread counter ownership. They must test link publication, callback/read lifetime and exact ownership, not merely duplicate the helper statements. The earlier prepared `../m14-perf-group-close-actual-body-1/` fixture is unexecuted and not offered as evidence; its unrelated accidental replay is preserved in `REPLAY-INCIDENT.md`.

This is an explicit no-go until a source- and ABI-bound lifecycle design receives independent ownership/concurrency review and is jointly integrated with the other worker's transaction; actual generated profile, link and native checks remain separate. `INPUT-HASHES.json` binds the compared actual candidate sources.
