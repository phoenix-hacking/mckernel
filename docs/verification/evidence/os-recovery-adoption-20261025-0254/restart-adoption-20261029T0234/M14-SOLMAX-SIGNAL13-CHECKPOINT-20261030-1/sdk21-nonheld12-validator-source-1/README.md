# SDK21 twelve-provider artifact adaptation — source only

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.
This private adaptation does not authorize execution or claim an SDK21 result,
release, default selection, ABI, native behavior, file retirement, current-free,
or cleanup. No HOST diagnostic is used as SDK evidence. The profile, original
389 tuple reference, input template and all validator nodes are authenticated at
their frozen hashes; node source, AST and segments are loaded without executing
the original scripts. The existing `registry`, `compare`, `Final`, `own`,
`allocated` and `relocated_function` are unchanged. The original exact
389 file/function/format/line/flags multiset remains the oracle. The semantic
context delta is recorded in THREE-OBJECT-CONTEXT.diff; it is not a patch to
historical evidence.

Inputs are deliberately unset in INPUT.TEMPLATE.NOT-AUTHORITY.json. A future
independently reviewed producer must supply `--work` (physical root mapping
`/work`), `--worker` (four actual command records with exact profile argv, cwd,
returncode and output path/bytes/hash), and `--binding` (completed copy of the
template). Actual SDK21/tool identities, execution receipt, ownership/currentfree,
producer and dependency provenance must be checked independently: this program
cannot establish those by reading self-reported JSON. No receipt is manufactured.

`old_objects.generic` and `.arch` must each be a nonempty list of authenticated
`{path, bytes, sha256}` references independently reviewed as the complete
relevant prior generic and arch link candidates, including the old selected C
objects and the prohibited HOST generic and old arch objects identified by the
profile. The adapter rejects byte reuse, checks exact eleven argv input tokens,
eight retained bytes, the ordered eleven `LOAD` object rows in the link map and
the link depfile, and witness-named ELF symbols and sections. The independent
reviewer must verify excluded identities and bind the map to the actual linker.
An exact input list excludes witness
objects by path; symbol/section name checks do not prove absence of all possible
unnamed witness data.

For each of `dependencies.rust`, `.generic`, `.arch`, provide the ordered tokens
from the respective actual compiler depfile's first make rule, each as
`{"token": "...", "actual_file": {"path": "...", "bytes": N, "sha256": "..."}}`.
The adapter authenticates every referenced byte, and compares the complete token
sequence, not just a subset. Independent review must establish each token's
container-to-physical resolution, SDK/system headers and generated files, and
must account for any additional make rules or escaping unsupported by the simple
first-rule reader. A parser mismatch is not permission to omit dependencies.
The link depfile is separately checked for the exact object-token set.

`arch_full_source_origin` requires `source_sha256` of
`78546125873dbf1f3619c2ce678bf9a07cc306b72db73f4597cc3d85ac4146de`,
`source_logical_path` `/src/arch/x86_64/kernel/syscall.c`, authenticated
`staged_source`, `receipt` and `independent_review` references. The receipt
input must bind `profile_sha256`, `staged_source` (same reference), and
`logical_path`; the staged source must appear in the arch depfile with that
logical token. The reviewer must establish real compiler operand, actual source,
source-map, macro coordinates, receipt substance and header provenance. The old
b5e9 receipt does not establish this full source. If actual reviewed receipt uses
another schema, adapt this source in a separately reviewed successor rather than
inventing an equivalent receipt.

The twelve selected symbols must each be one strong FUNC in the new Rust object,
absent from other inputs, shape-matched to the image, with unchanged authenticated
full final bytes and relocation checks. Sharing an address between the two actual
constructor alias pairs is permitted. The listed C residuals are reported and
`do_signal` must remain in the arch C object; other inherited consumers, binding
objects, ABI and unsupported relocation forms need the established full artifact
and independent reviews. A failed assertion means observations did not pass; it is
not an accepted regression or a reason to weaken the original comparator.

Future execution, including even this read-only adapter, requires the applicable
reviewed profile and resource/ownership release. Output uses exclusive creation
and is intentionally `BOUNDED_ARTIFACT_OBSERVATIONS_ONLY_NOT_ACCEPTANCE`.
The required producer, SDK21 origins, consumer/caller checks and native proof
remain open. Held generic_c direct-TID/terminate_host and execve transfer/ACK
and equivalent work remain excluded; whole do_signal and FULL28 remain off.
