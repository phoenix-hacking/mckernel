# Private signal comment correction

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

This separate private patch replaces two lines in the `do_signal` safety comment. It removes the stale claim that the diagnostic counter races are preserved after the PRIVATE-2 atomic overlay, while retaining the separate statement that overwritten old core slots are existing debt. Apply it only together with the reviewed PRIVATE-2 atomic change; applying it to the original unsynchronized body would make the comment inaccurate. The generator compares all `line!`, `file!` and `column!` source sites and preserves their line and column positions. Its output includes SHA-256 bindings. It changes no executable source; no compiler or test was run for this correction.

PRIVATE-2 stores PID bits and a count in one relaxed atomic word. Each `do_signal` entry observes its PID and resets the count only if it differs from the current word's PID. At either logging site a successful atomic increment reserves a slot before `kprintf`; a count of 64 suppresses another claim until a PID change. A reentrant or concurrent formatter sees the already reserved slot and cannot claim beyond 64 in the same unchanged epoch. This deliberately differs from original C, which checked before `kprintf` and incremented after it, and had unsynchronized shared counters. A reset can occur while an earlier claimed log is still printing, and a delayed invocation claims against the then-current epoch rather than restoring its own PID. PID interleaving can repeatedly reset the shared budget, so this is neither a per-PID lifetime quota nor a bound on output over multiple epochs. Relaxed operations do not order output delivery or other signal state. No equivalence to the original behavior under reentrancy or races is asserted.

The selected source and this comment change require compositor integration and independent review. The original C, private atomic overlay and previously retained evidence remain unchanged.
