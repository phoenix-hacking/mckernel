# Perf event tail and clone ownership: source-bound blocker

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. No Rust patch selected; no compiler, tests or live operations. INPUT-HASHES.json binds the retained f06 candidate and separately identified canonical context. Candidate/assembled-source selection and native evidence are not established by this report.

The real selected `f03_perf_event_allocate_v1` passes `size_of::<FullMcPerfEvent>()` and C-compatible field offsets to `perf_event_alloc_body_result` (retained syscall_policy.rs:36563, :20910). That body allocates the specified size and releases the same base on initialization/map error; its selected bridge uses tracked kmalloc/free (:35975-35992). The original event fields have the C order in FullMcPerfEvent (:35779) and canonical lib/include/mc_perf_event.h:244. Thus a freshly allocated Rust `#[repr(C)]` object with the event at offset zero and an appended, suitably aligned tail is a plausible ABI-preserving *representation*: event address and offsets can stay unchanged, and the base pointer can still be passed to tracked free. It is not currently such an allocation. A real change must separately bind allocation extent/initialization, size conversion and layout equality, all old/new providers and error free ownership, without interpreting legacy-sized objects as tailed allocations. A tail cannot itself make references safe.

The retained perf descriptor publisher writes neither `dup_cb` nor `opt` (syscall_policy.rs:21197), and its kmalloc_tracked bridge delegates to `_kmalloc` without zeroing (mem_helpers.rs:4173). Accordingly these fields are not initialized by this publication path; zero cannot be assumed. Clone copies descriptor bytes then tests and invokes copied `dup_cb` with `(copied_mckfd, NULL)` (process_helpers.rs:13910-13940 and :8548). It locks the destination proc while traversing the parent list; no parent-lock protection is established by that loop. The dup callback's return is ignored and failed-fork drain frees descriptor copies without close callbacks (:14028), so successful reference acquisitions would require explicit rollback and synchronization with close. Simply zeroing `dup_cb` avoids neither the copied raw event pointer nor multiple close callbacks freeing the same event.

A direct concrete race blocks a tail-only refcount: with clone traversing its unpinned source, close may detach and free the parent descriptor/event before clone reads its copied data or calls the dup callback. Incrementing a tail after reading a stale event pointer cannot recover its lifetime. The same issue affects concurrent read/ioctl/fcntl/mmap: lookup drops `mckfd_lock` before callback use (:3496-3722), and close frees after unlock. Retained x86_cpu_helpers.rs:3663 has a separate IRQ lookup/after-unlock descriptor use. Lock acquisition, descriptor and event reference acquisition, detached/closing state and last-use release must be integrated across these sites and process lifecycle before a tail can be consulted safely.

Descriptor references are also not the complete event owner set: perf ioctl writes raw event to `process.monitoring_event` (retained syscall_policy.rs:20471); the retained scheduler reads that pointer for perf_reset/perf_start (x86_cpu_helpers.rs:5459). In canonical source clone/inherit copies that pointer (kernel/syscall.c:8269), and process termination calls sync_child_event on it (:5334); actual selected route and ordering must be bound. `perf_stop` clearing the current process monitoring pointer does not establish all remote/inherited monitoring owners have retired. Event/group readers traverse raw leader and list links; leader-first close, member unlink and transactional group publication must also hold compatible pins. Counter allocation and last release need an explicit opener-thread or stable-owner lifetime and lock contract; current close uses closing thread maps.

Required first integration contract: atomically acquire source descriptor and shared event ownership while source list is protected; define lock order with child publication and distinguish each descriptor clone, in-flight callback, monitoring owner, group leader/member and scheduler reader; provide rollback for every clone/open failure and a nonblocking last-release protocol for callbacks currently invoked under process spinlock. It must bind the exact assembled source choices, address pointer reuse and failed/unknown host completion, and permit no spinlock across host syscall. No existing source offers those facts. Thus no safe actual-body patch or meaningful runnable regression can yet be honestly supplied, even though a tail layout may preserve offsets. Independent ownership/concurrency review and a reviewed execution profile remain prerequisites.
