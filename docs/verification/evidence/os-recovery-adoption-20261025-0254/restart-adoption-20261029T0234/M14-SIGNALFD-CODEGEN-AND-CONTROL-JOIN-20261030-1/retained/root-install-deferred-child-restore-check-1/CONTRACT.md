# One-child DeferredFork restore probe

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. Source-only proposal. No test, fork, root operation, signal to another process or cleanup has been performed. It does not inspect, alter, retry or clear the existing UNKNOWN install operation or its 4 GiB reservation.

The fixed source loads the exact SHA-bound source10 `DeferredFork`, `ChildRecord`, pidfd compatibility, pidfd custody and graph observation modules. It installs the same `on_stop` handlers and active self alarm as the parent and enters a `SIGALRM`-blocked outer mask around the exact production guard. A test-only `ReportingGuard` calls the unchanged production `_restore(child)` and, if that call fails before the child callback, makes one bounded write to its private result pipe before re-raising. On success the sole direct UID1000 child records its post-restore mask and handler observations to that pipe, waits for the parent's one-byte gate so the parent's actual pidfd/birth acquisition can finish, then calls `_exit(0)`.

The parent checks that the actual callback mask matches its mask immediately before guard entry and the configured stop handlers were restored, polls the actual verified child pidfd, directly waits the actual child, and records single-attempt close dispositions for owned pipe and verified pidfd descriptors. A raw pidfd from a failed verification is not treated as verified or retried by numeric descriptor. No PID or group is signalled by the probe. An unproved child terminal, fd disposition, short output or other error is UNKNOWN and requires the outer Root process owner to retain its actual resource reservation; no success or cleanup can be inferred.

Static source inspection found no deterministic `_restore(True)` defect: configured signal handlers are restored, the mask saved after outer SIGALRM blocking is reinstated, and the guard lock is released in the child. The actual behavior of the inherited lock and CPython 3.8 restore path needs this concrete real-fork observation. The probe cannot diagnose failures that happen later in the actual keeper's `direct_entry` or phase-zero path, or prove the previous keeper's cause.

The exact prospective argv is in `PROFILE.SOURCE-ONLY.json`. The outer `timeout --foreground` preserves the 45-second/TERM+5-second bound without a process-group signal; on an outer timeout the actual Root owner must separately account for any still-owned child and retain UNKNOWN until positive terminal evidence. Root must create the fresh private output and TMPDIR, bind the exact Python/tool/source bytes and actual recorder/PID/birth, and independently recheck live controls, the original weekly guard/caps, CPU6 and resource floors before any one-shot execution.
