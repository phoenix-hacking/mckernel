# Install-only failure DATA: source patch proposal

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. This is a private source correction against the frozen Parent4 `root_parent.py` SHA-256 `ffdad75a89dd433fa459968a3758e28d24809119698ba0afb2fd7ffbc02eeba3`. It does not modify the live UNKNOWN attempt, its reservation, process state or any SDK-owned source; it is not a replay or an operation release.

The proposal adds a one-attempt, maximum 4096-byte canonical JSONL failure record to the existing stderr regular capture. It reports fixed stage and role, actual exception class, actual observed Root and keeper PID/birth (null where not observed), native release false and native current-free null, and UNKNOWN outcome. It never includes admission bytes, environment, credential material or arbitrary exception text. A single-argument error message is emitted exactly only if it equals a fixed literal extracted from the bound parent/child sources; otherwise a standard system errno message is emitted without any filename, or the message is explicitly redacted. `FIXED-MESSAGES.txt` records the extracted literals; the frozen proposal contains its own exact list. This is diagnostic DATA, not a statement of custody, release or successful cleanup.

The child callback reports setup or direct-entry exceptions to inherited stderr before re-raising into the existing DeferredFork exit path. The parent retains its original latch, pidfd/stop, deadline, wait and indefinite UNKNOWN behavior, and attempts the diagnostic only after existing best-effort owned-child stops and before the UNKNOWN hold. The post-proof `serve` exception path likewise attempts a diagnostic before its existing hold. For each report the code performs one write, requires the entire record length and then fsyncs; a short write or any exception is not retried. A failed diagnostic cannot establish an operation outcome. The existing outer owner must preserve the actual stderr capture and determine observation and process status independently.

`test_failure_data.py` supplies mocked exact safe-message/identity, arbitrary-message redaction, short-write/no-retry and actual parent `serve` ordering tests. The cases, source and patch are unrun; no root operation, signal, cleanup, live observer or test was launched. SDK owns integration of the proposal into any separately reviewed future parent/bootstrap/caller, including exact source and capture bindings. Actual execution remains blocked by the existing UNKNOWN ownership and requires its normal independent review and operation admission.
