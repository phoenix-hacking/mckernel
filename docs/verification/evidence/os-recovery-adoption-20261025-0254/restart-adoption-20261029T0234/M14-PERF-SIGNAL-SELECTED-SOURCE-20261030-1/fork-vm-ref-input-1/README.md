The private `do_fork.VM-ABORT-PIN.PRIVATE.rs.inc` candidate acquires a VM reference only on the pre-chain CLONE_VM error edge, before the existing caller-thread pin is dropped; the existing final thread destructor is expected to consume that reference. This avoids changing successful publication, chain status handling or constructor-internal failures, and does not double the chain-issued edge. Its validity depends on the live parent retaining the borrowed VM and on the original abort having exclusive authority to perform final thread release. Those assumptions need independent ownership review. In particular, resetting thread refs on error cannot be justified merely by the constructor's initial count if external references have escaped. The separate success publication still uses a void `chain_thread` which discards `chain_thread_checked` status; the checked chain can publish both lists before its VM increment and does not expose a separately durable publication receipt.
