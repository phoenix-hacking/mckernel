# Perf event and group lifetime: conditional source-bound design

Functional McKernel OS/apps and Rust/assembly migration only; no security testing. This is an unimplemented design, not a source fix, test or acceptance. INPUT-HASHES.json binds the retained source. Generic descriptor lifetime is separately owned; its worker reports there is no usable pin/close handoff ABI yet. No physical operations or tests ran.

First blocker: `perf_ioctl_body_result` writes a raw pointer into `process.monitoring_event` (syscall_policy.rs:20471), but `arch_switch_context` reads it repeatedly and invokes perf reset/start without a demonstrated common event lifetime lock (x86_cpu_helpers.rs:5459). The process-exit path also reads it and runs `sync_child_event` (syscall_policy.rs:35623), which traverses leader and siblings. Without an established atomic acquisition and retirement contract for this published process pointer, any last-close release may race an IRQ/scheduler/exit reader. Retaining a descriptor reference cannot prove it safe, because monitoring is a separate owner. The exact selected inheritance, process destruction and CPU-switch paths need to be bound before implementing or proving a pin protocol.

A concrete candidate architecture, conditional on the missing provider contracts, is an event-first `repr(C)` allocation with a Rust-owned aligned tail containing a generation/type marker, group pointer, refcount and explicit lifecycle flags. Retained allocator (syscall_policy.rs:20910 and :36563) accepts an extent and initialises that entire extent to zero (:20713), but the new owner must initialise atomic/lock values explicitly and preserve the event at offset zero, exact base-pointer tracked free, errors, C size/offset proofs and source selector pairing. Only allocations known to come from the new provider may be cast to this tail; no automatic conversion of legacy or mixed-selected events.

A separately owned group object would provide one short-held lock and a stable lifetime anchor. Each linked member owns a group reference; the group owns a leader event reference while any member or in-flight group operation exists. Each descriptor including every fork copy owns one event reference, acquired under a live source-descriptor pin before copy publication. Readers that need event/group data hold a descriptor, monitoring or transient operation reference and acquire the group lock to snapshot or manipulate links; if they need to use a member after unlock they acquire its event pin while still locked. Descriptors have `open`, `closing` and `closed` state under the separately reviewed descriptor protocol; detach prevents new acquisitions, and event reference release happens after callback/read users have retired. Counters and event bytes must not be freed on intermediate descriptor close.

For member close, the owner would unlink it under the group lock, update sibling count and aggregate status consistently, then release the list-owned reference outside the lock. A descriptor-close request must define exactly when the member is considered logically closed relative to in-flight operations and host close; the last-descriptor-versus-first-descriptor rule for cloned FDs is unresolved. For leader-first close, retain the leader allocation and group anchor while members/operations/monitoring still refer to it; do not treat the retained allocation as automatically visible in a read or PMU operation. The user-visible meaning of leader close and group operation after that event must be specified and tested against the intended semantics before selecting anchor behavior. Last free requires zero descriptor, group, monitor and transient refs, successful cessation or transfer of hardware ownership, and exactly one release of the original allocation.

Grouped open would acquire a pinned parent descriptor and leader/group reference, reserve a unique counter under the owner protocol, and allocate event and local descriptor privately. Drop all spinlocks for host syscall. After successful offload, acquire the agreed lock order, revalidate group and owner state, and atomically publish the membership and FD with ownership transfers. For known prepublication failure, reverse only known completed effects, including reservation, group/event refs, descriptor and any proven owned host FD. Host close has an independently bound completion/error contract; unknown close/outcome cannot be counted as rollback or freed. Group disappearance and fd publication collision must have explicit outcomes. This arrangement intentionally does not refuse grouped calls.

A process monitoring slot must itself own a group/event reference. Installation, replacement, scheduler acquisition, inherited handoff, stop and process exit need a lock or atomic protocol jointly usable in interrupt/scheduling contexts; the slot cannot be freed or replaced until all acquired readers release. Lock order with descriptor/group locks and process/CPU switching must be specified and verified, and calls that can block must happen outside spinlocks. The retained `perf_stop` clears only the current proc slot (:20447); this is not proof that other process slots or concurrent scheduler readers retired. No suitable existing shared synchronization or ownership handoff is established.

The actual x86 `ihk_mc_perfctr_alloc` (:435) scans `thread.pmc_alloc_map` and returns an index; `perf_event_open_linux_fd_body_result` sets that map only after host success (:21148), whereas `perf_close_body_result` (:20558) clears the closing current thread's maps. A correct design must bind each reservation to a stable, live counter-owner object, serialize reserve/commit/release and coordinate owner-thread exit and remote close. A raw opener Thread pointer plus refcount is insufficient without a source-bound thread pin and a lock/remote-map mutation contract. The exact extra-register reservation and PMU migration/provider semantics remain to be established.

Generic worker's current handoff cannot yet guarantee callback-held pins, source clone exclusion, rollback or finalization outside the process spinlock; close callback is context-sensitive and teardown calls callbacks under the lock. Those facts and the monitor handoff are concrete blockers to an actual safe patch. Once source and lock contracts are independently reviewed, actual-body regressions must cover member-first close then append, leader-first close with surviving members, clone and failure rollback, callback/close and monitoring/scheduler interleavings, cross-thread owner exit, no host syscall under spinlock, one final tracked free, and host unknown outcomes. Use a reviewed light profile; none was executed here.

The generic lane identified an additional snapshot constraint: `f03_perf_fcntl_v1` writes F_SETSIG to the real descriptor sig_no, which IRQ subsequently reads. Invoking it on a local descriptor copy would lose that state; a perf-only snapshot requires a synchronized store/IRQ snapshot protocol. A snapshot event pin can be acquired while the process descriptor lock still protects a known live selected event, but it does not by itself establish cloned descriptor, group or monitoring ownership.
