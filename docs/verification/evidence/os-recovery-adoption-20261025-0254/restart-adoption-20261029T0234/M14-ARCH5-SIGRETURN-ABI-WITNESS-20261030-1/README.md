# Private native signal-return ABI witness source

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

The retained ARCH5 61-slot witness covers total native frame size/alignment, `fpregs`, `info`, `sigstack` and GS/TSS offset, but does not cover the native `sigreturn` frame register/mask offsets, accessed context register fields, or its `thread.vm -> region -> user_start/user_end` path. This supplemental 40-slot witness generates paired data arrays using the actual native C `struct sigsp`, `stack_t`, thread/VM and x86 context types, and corresponding Rust types; `GEOMETRY.json` gives their exact ordered expressions. It contains no replacement type definitions, pointer casts to fabricated geometry, executable code or runtime effect. No compiler, test, build, or guest was run. Generated hashes are in `RESULT.txt`.

Integration is deferred to the compositor and operation owner: include `sigreturn-extra-abi.inc` after the real local `struct sigsp` in the selected native x86 translation unit, compile `sigreturn_extra_abi.rs` as a temporary crate module against the selected actual Rust sources, and extract and compare all 40 ordered little-endian LP64 values from their distinct sections under an independently reviewed compiler profile. Preserve source and build identity. Do not add witness data to a production/default image or conflate a matching object comparison with linked/native acceptance. This uncompiled source may need correction if actual selected preprocessing/types or build bindings differ.

## Source trace and remaining obligations

- `sys_rt_sigreturn` calls the optional-output context bridge in thread, xsave-size, register order. The retained context candidate gets the current thread from `get_this_cpu_local_var`; that provider resolves `ihk_mc_get_processor_id()` into the CPU-local array. For registers it reads GS-relative packed `tss.rsp0` and subtracts one actual `X86UserContext`. Existing C uses the same GS load and subtraction. `ihk_mc_set_kstack` updates architecture-local `kernel_stack` and `tss.rsp0` in the selected path, but source layout alone does not establish that these readers refer to the same current CPU, that migration/interrupt exclusion holds, or that the complete stack context remains live through callbacks and publication. Preserve those runtime/assembly obligations and review generated code; do not execute GS helper on the host.
- Under `native_linux_irq_work_v6_12`, `sys_rt_sigreturn` calls `native_signal::sigreturn`: it copies an entire `Frame` into kernel storage, checks the live thread/VM and frame RIP/RSP against current user bounds, calls `arch_native_signal_restore_fp_bridge`, then publishes registers, mask and alternate stack only after FP success. The local frame and thread/context/VM must stay live across synchronous copy and restore. The 40 slots add geometry coverage of the fields actually consumed; they cannot prove ownership, CPU continuity, copy success, sequencing, or native execution.
- The native FP provider resets on null user FP address; otherwise it checks the supplied and boot configured size, allocates enough space plus alignment slack, copies user state, validates alignment/standard-format and feature constraints, invokes checked XRSTOR, and frees the original allocation on post-allocation paths. Matching buffer size, current CPU, stable boot mask/XCR0 and suitable exclusion remain runtime and codegen obligations.
- `arch_rt_sigreturn_xrstor_bridge` instead supplies the raw XRSTOR leaf to the **non-native** configuration path. ARCH5 reuses the actual boot mask and Rust asm splitting full mask into EDX:EAX. Alignment, readable extent, valid standard state, no generated FP/SIMD, CPU/exclusion and raw-fault behavior remain explicit obligations. Converting or qualifying this leaf alone does not prove native sigreturn exercised it.

No equivalence, whole-source ABI pass, final link, original scope acceptance, or actual hardware operation is claimed.
