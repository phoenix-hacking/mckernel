Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

Private source-only request constructors cover `syscall_do_syscall2_bridge`, `syscall_policy_do_syscall2_bridge`, `syscall_do_syscall3_bridge`, `syscall_policy_do_syscall3_bridge` and `wait_host_wait4_bridge`. The approved narrow contract ca85a6c4 specifies number and all six wire arguments, including readable/marshallable zeroes in unprovided slots; this is deliberately defined behavior, not parity with the old indeterminate C bytes. The single local helper writes those seven fields individually through raw field pointers in MaybeUninit storage and calls existing `do_syscall` with the current processor. It does not write sender IDs, valid, response, packet or UTI storage, form references to an uninitialized whole SyscallRequest, add errno/number checks, or change the existing helper. The object has 64-byte stack alignment while the existing repr(C) request remains 72 bytes and 8-byte aligned. Request number and wait4 pid/options use direct signed-int to unsigned-long conversion; wait4 preserves the C long-to-int return conversion subject to selected ABI verification. `__NR_wait4 = 61` is checked in the x86 header.

The constructor is NOT selected by default: `MCKERNEL_F03_REQUEST_CONSTRUCTORS_EXPERIMENTAL` must be explicitly enabled in the existing paired Linux 6.12 x86_64 non-UBSAN C/Rust branch. This source switch is a proposal for future authorized compile and is not authorization to enable or execute it. In other configurations the token-identical original C functions remain. This patch is based on the ten-callback postimage; the compositor must rebase its C/CMake/syscall_policy regions alongside other independent contributions, preserving all existing content and file/line sites. Actual selected-callgraph closure against the exact reviewed syscall-number sets, extra semantics in any unused slot, selected profile and full 29-word packet ABI are still open. The existing C `do_syscall`, helper initialization order, response and endpoint/ownership lifetimes remain explicit dependencies and are not retired by this candidate.
