Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

Two minimal private patches and an explicit request contract are ready for Root disposition. They are not selected or compiled and do not clear any existing hold.

`exec-long-diagnostics.patch` applies to the previous private whole exec source: the two original `%d` diagnostics receive a `long` and have undefined variadic type behavior. The proposal uses `%ld` and passes the same `CLong`, preserving the signed value, event, metadata, and order. It does not claim parity for undefined behavior. The 32-word C/Rust witness and all other source bytes are unchanged.

`exec-request-arity.PROPOSED.rs.inc` and the accompanying declaration/witness propose concrete constructors, not a finished selected transport. Phase 1 explicitly receives the number, dirfd, filename, physical descriptor, flags, and a transport-owner-provided seed for `rtid`, `ttid`, `valid`, and arg5. It writes a whole initialized request with args0..4 = phase 1, sign-extended dirfd, filename, descriptor address, sign-extended flags; arg5 is the explicit seed. Phase 2 requires the same fully initialized request be exclusively owned after phase one, updates number and args0..2 = phase 2, descriptor address, byte length, and preserves all other fields. The request/seed C and Rust witness arrays and aggregate-by-value calling convention require actual ABI/compiler qualification. The prior whole exec candidate declares different unresolved constructor names/signatures; Root must choose and wire one contract, not silently link these proposals.

Selected executor source observes args0 for dispatch; phase 1 reads args1,2,3,4 and phase 2 reads args1,2. On the selected offload path `syscall_offload_prepare_result` writes request rtid/ttid and `syscall_send_prepare_result` writes valid before copying; full publication requires all non-valid fields initialized. This confirms why explicit arg5 remains needed, but does not establish any value for it, all consumers, transport timing, or an acknowledgment. Decide valid seed and arg5 semantics and bind `__NR_execve` from the actual header. Verify the same request is no longer borrowed before phase 2 mutates it; verify the host producer/transfer fits the four-page descriptor and shebang storage; define filename/flattened argv/env ownership and response/ACK before reclaim. On phase 2 fatal host failure the executor may exit without an ordinary response; no ACK or cleanup authority is inferred.

`fork-tid-snapshot.patch` applies exactly once to the retained complete mmap/fork policy. The original CURRENT119 C body occurs exactly once in the frozen preimage. In its CLONE_VM reporting path, report attach and lock release precede hold, enqueue, optional schedule, and final new->tid read. The corrected helper preserves report/hold/enqueue/schedule order while snapshotting TID immediately before enqueue. Source inspection finds no `new` mention after enqueue in that helper, and the whole fork caller directly returns that helper result; it does not inspect the child after the helper returns. The change assumes the committed TID is stable until enqueue and the child remains live through earlier ptrace/report/snapshot. Child retention before that point, report attachment, ptrace reservation, constructor/CPU ownership and parent/VM lifetimes remain unproven. Scheduler provider ownership remains independently reviewable.

`python3 -B check_source.py` passed exact replacement checks, frozen fork provenance, publication ordering, absence of a post-enqueue child reference and request field source assertions. These tests are static and do not prove generated code, ABI, actual concurrency behavior, runtime, native qualification or C retirement. No native operation or controller mutation was performed.
