# Finite independent build review protocol

Functional McKernel OS/apps and Rust/assembly migration only; no security testing.

This specification supplies the otherwise-passed CURRENT115 predicates after
the preserved Resource1 expiry. It grants no observation, holder or build action.
Future admission/nonce/current ledger remain unbound until genuine Root inputs.

Use separate `verify_ref` and `read_json_ref`. The former reads stable regular
bytes and compares exact path/size/SHA, without JSON decoding Python/ELF files.
The latter additionally requires complete UTF8 JSON, duplicate-key rejection
and the expected top-level type. Never accept partially written or trailing JSON.

Cold phase, before resource clocks:

* Freeze exact final admission directory, actual fresh nonce, request/adoption,
  profile+all four argv, runner/worker/holder/export, Root current boundary and
  accepted source/materializer/observer reviews. Reject NULL/future descriptors.
* Validate the complete new publication/static/source closure here, including
  exact fetched publication context and genuine origin. Reuse explicitly retained
  accepted eight objects/SDK references at their accepted scope. No broad source
  loop belongs in the hot phase. Preserve 120 Rust sources/three new/eight retained
  objects and all original flags/ABI/ownership/native limits; no artifact acceptance.
* Validate exact Root ledger and latest physical-clearance provenance, nonce
  unused/not abandoned, all holds, fixed caps, original account and clock contract.
  No actual account/resource/process/Docker/holder query occurs in cold waiting.
* Precompute the tiny receipt fields and exact final receipt path. Root publisher
  reserved attestation/grant/READY paths remain untouched by the reviewer utility.
* Finish pure fixture/static checks and independent source review before launch.
  The independent reviewer alone invokes this exact reviewed program/contract.
  It emits durable `PREWARM_READY` only after successful cold checks, with its
  actual self PID/birth, utility+contract/cold-proof refs, nonce and exact marker
  and receipt paths. It then actually waits for the one predetermined marker.
  Root verifies this same live identity/READY before starting capture clocks.

Root complete-capture protocol:

* Root alone writes one atomic, exclusive completion marker after the actual
  reviewed capture has returned0, its direct child positively joined and both
  streams closed, with expected complete resource and pending files in place.
* Marker pins actual join, resource, pending, preholder physical and holder READY
  refs, exact same nonce/profile/request/utility-contract context and PREWARM_READY.
  Marker is metadata, not a grant. No inferred completion from file existence,
  a running capture, absent stderr, partial JSON or a wrapper that has not joined.
* On any exception/nonzero/uncertain capture: publish no success marker, preserve
  failure/namespace, and no Root publisher/build READY. Never renew120s or retry
  inside this verifier. Only the original fixed campaign clamps apply.

Hot phase, once, after complete marker:

* Authenticate marker and actual complete0/join/closed-stream capture. Read only
  the new small exact pending/resource/holder/bootstrap/Root-input refs and the
  bounded actual physical JSON once. Compare static refs to cold frozen digests,
  without walking source/export/object/toolchain closure again.
* Apply `hot_predicates.py` equivalently, original approved runner resource guards
  and actual clock/account/custody requirements at their existing scope. Check
  actual sole holder birth/FD/flock, captured headroom/cgroups and no prior launch.
  No source-body review, report prose generation or subprocess discovery here.
* Reject if any Root publisher attestation/grant/build READY/RUNNER.STARTED/OUTPUT
  exists before review; verify that the prewarmed reviewer identity still matches.
* Compute actual pending SHA from the complete authenticated file. This exact SHA
  becomes `payload_sha256`/`approved_input_sha256`; it is not an old literal or a
  guessed future value. Root later uses its existing explicit publisher CLI.
* Tiny final receipt: PASS_EXACT_BUILD_ONLY_EXECUTION, independent:true,
  implementation_ownership:false, reviewer:/root/custody_release_review,
  nonce/max1/exact pending+resource refs/SHA, holder, cold/PREWARM_READY/marker refs,
  final actual age<=120 and earliest three clamps. No build/native acceptance.
* Prepare and fsync only a private unpublished temporary file, then recheck the
  exact packet/resource identities, original freshness and all clocks immediately
  before exclusive atomic publication of the final receipt. Do not overwrite.
  A failed/stale check publishes no PASS and exits; preserve refusal evidence.
  No source-author action, publisher call, grant, READY, Docker/compiler or signal
  is part of this independent review utility.

Root alone reads the actual reviewer receipt/approved SHA and invokes the already
reviewed publisher. Source author must not run the adopted hot verifier or label
their own prepared checks an actual independent approval.
