An ordinary executable fixture cannot produce missing or partial setup because

## Exact cases

Missing setup records a bounded child-stderr witness at the READY boundary and
exits 0 without writing setup. Partial setup serializes the real READY words,
writes exactly 383 bytes through the real setup pipe, records the actual write,
and exits 0. Any diagnostic or write failure is an independent harness failure.
Both require collector exit 1, raw child wait 0, setup length exactly 0 or 383,
all pipe EOFs, no READY/error/validated flag, no post-exec observation, and first
failure `SETUP_ERROR/setup-pipe-incomplete/EPROTO`.

Completed-wait uses the unchanged `stdin-devnull` fixture. Its injection runs
only when the actual leader is waitable but unreaped, completion was observed
within the process deadline and no earlier failure exists. It records that
boundary, calls real `raise(SIGTERM)`, verifies return and the caught signal,
then resumes the unchanged main path. It requires valid 384-byte setup, exact
`DEVNULL\n`, raw child wait 0, collector exit 1, signal 15, first failure
`INTERRUPTED/collector-interrupted/EINTR`, complete cleanup and all EOFs.
No sleep, external numeric-PID signal or direct interruption-flag assignment is
accepted. Stimuli run in separate processes so first-failure preservation cannot
mask another case.

Builds use the pinned C11 warning-error profile, real request/SHA objects and
complete compiler/dependency/ELF bindings. The new root path must reproduce the
existing isolation, watchdog, ownership, cleanup and lock-release contracts;
the existing six-input/25-result profile cannot silently consume these binaries.
The reviewed per-case and whole-container bounds remain 40/15 seconds and the
four-CPU/12-GiB limit remains in force.

Negative controls reject disabled-control failure, changed source or patch
anchor, absent/unknown compile guards, wrong setup prefix length, missing
boundary witness, wrong raw wait, incomplete cleanup, and a misleading
`COMPLETED` status. Retain source/compiler/ELF bindings, generated source/diff,
requests, diagnostics, setup bytes, both streams, reports/events, raw waits,
PID/startticks, deadlines, container inspections, watchdog result and final
absence.
