McKernel Rust Port Plan With Controlled Verification
Updated: 2026-05-17

Purpose
------------------------------------------------------------

This document records the Rust migration work completed so far and defines the
full granular plan for porting McKernel-owned implementation code to Rust. The
verification strategy is intentionally staged: each checkpoint tests one layer,
has a clear success result, and stops before later layers make debugging noisy.

Definition of "fully ported"
------------------------------------------------------------

The target end state is:

- McKernel-owned non-assembly implementation logic is Rust-owned.
- Existing public C headers remain as compatibility surfaces while external
  users still depend on them.
- Rust replacement functions use the existing C ABI and exported symbol names.
- Architecture entry, interrupt, trampoline, and context-switch assembly remain
  assembly unless a later phase explicitly replaces them.
- Linux kernel internals and third-party code are not rewritten.
- Host/user components are ported where technically supportable by the target
  kernel and toolchain. If external Rust Linux modules are not supported, keep a
  small C module shim and move pure logic behind C-callable Rust interfaces.

  no red zone, large code model, static relocation model, frame pointers, no
  vectorization, no unwinding, and no allocator.
- Updated the x86_64 linker script to include large-model Rust text sections.

- Added C-side ABI/layout checks in kernel/rust/abi_checks.c.
- Covered the first shared syscall/protocol structures needed by the migration.
- Preserved public C headers, symbol names, syscall numbers, ioctl values, IKC
  packet formats, and linker-visible entry points.

Public interface rules
------------------------------------------------------------

- Preserve syscall numbers.
- Preserve ioctl values.
- Preserve IKC packet formats.
- Preserve exported symbol names.
- Preserve public C headers during the migration.
- Use extern "C" for Rust functions replacing C implementations.
- Use #[repr(C)] for all shared ABI structs.
- Keep union-heavy and flexible-array-heavy interfaces pointer/raw-layout based
  until each call site is deliberately migrated.
- Do not make behavior-breaking ABI changes without a separate approved plan.

Controlled verification ladder
------------------------------------------------------------

Run the steps in order. Stop on the first failure. Do not proceed to runtime
checks until all earlier build and equivalence checks pass.

- git diff --check

  code.

V12: Phase-specific stress
--------------------------

Purpose:
- Keep future verification narrow and debuggable.

Rule:
- Each Rust port phase gets tests specific to the code just moved.

Examples:
- Allocator phase: allocation/free/coalescing stress before syscall tests.
- Page-table phase: mapping/unmapping/attribute tests before process tests.
- Futex phase: futex stress before file-object tests.

Success:
- The new Rust phase passes its specific stress tests, then passes V4 through
  V11.

Stop condition:
- If stress fails, do not port the next subsystem.

------------------------------------------------------------

-----------------------------------

- Docs accurately describe completed work and current limitations.
- V0 passes.

----------------------------------------

Scope:
- Improve CMake diagnostics for missing nightly rustc.
- Make the Rust target name and output path obvious.
- Ensure Rust build flags remain centralized and auditable.
- Keep ENABLE_RUST_KERNEL=ON and ENABLE_RUST_KERNEL=OFF equally supported.

- V1 through V5 pass.

---------------------------------

Scope:
- Expand Rust #[repr(C)] mirrors for syscall, IKC, process, memory, and x86_64

- V2 through V5 pass.

  generated bindings, or assembly-adjacent code.

Operating rules for every phase
------------------------------------------------------------

- One subsystem moves at a time.
- Each phase must add or update its own narrow verification.
- C and Rust behavior must be proven equivalent before removing C code.
- Runtime smoke testing must happen before broad regression testing.
- If a verification step fails, stop at that step and log the exact failure in
  kernel.log.
- Keep the system bootable after every merge.
