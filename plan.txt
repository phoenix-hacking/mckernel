McKernel Rust Port Plan With Controlled Verification
Updated: 2026-05-18

Purpose
------------------------------------------------------------

This document records the Rust migration work completed so far and defines the
full granular plan for porting McKernel-owned implementation code to Rust. The
verification strategy is intentionally staged: each checkpoint tests one layer,
has a clear success result, and stops before later layers make debugging noisy.

Definition of "fully ported"
------------------------------------------------------------

The target end state is:

- McKernel-owned non-assembly implementation logic is Rust-owned.
- Existing public C headers remain as compatibility surfaces while external
  users still depend on them.
- Rust replacement functions use the existing C ABI and exported symbol names.
- Architecture entry, interrupt, trampoline, and context-switch assembly remain
  assembly unless a later phase explicitly replaces them.
- Linux kernel internals and third-party code are not rewritten.
- Host/user components are ported where technically supportable by the target
  kernel and toolchain. If external Rust Linux modules are not supported, keep a
  small C module shim and move pure logic behind C-callable Rust interfaces.

Completed migration work
------------------------------------------------------------

Rust kernel build foundation
----------------------------

- Added a freestanding Rust kernel crate under kernel/rust/.
- Added no_std Rust code with panic abort behavior and no allocator dependency.
- Wired the Rust object into the x86_64 mckernel.img link when
  ENABLE_RUST_KERNEL is enabled.
- Preserved a C fallback path when ENABLE_RUST_KERNEL is disabled.
- Restricted Rust enablement to the current x86_64 migration target.
- Configured the Rust build for kernel-style code generation:
  no red zone, large code model, static relocation model, frame pointers, no
  vectorization, no unwinding, and no allocator.
- Updated the x86_64 linker script to include large-model Rust text sections.

ABI and layout foundation
-------------------------

- Added Rust ABI definitions in kernel/rust/abi.rs.
- Added C-side ABI/layout checks in kernel/rust/abi_checks.c.
- Covered the first shared syscall/protocol structures needed by the migration.
- Added ABI/layout checks for `struct rb_node`, `struct rb_root`, and
  `struct free_chunk` before moving page-allocator helpers to Rust.
- Added ABI/layout checks for `struct list_head`, `mcs_lock_node_t`, and
  `struct ihk_page_allocator_desc` before moving the bitmap-backed page
  allocator internals to Rust.
- Preserved public C headers, symbol names, syscall numbers, ioctl values, IKC

First Rust primitive replacements
---------------------------------

- Ported the kernel red-black tree implementation behind the existing rb_* C
  ABI.
- Ported linked-list helper routines behind the existing C ABI.
- Ported priority-list add/delete helpers behind the existing C ABI:
  `plist_add()` and `plist_del()`.
- Ported the pure waitqueue locked list core behind the existing C ABI:
  `waitq_init()`, `waitq_add_entry_locked()`,
  `waitq_remove_entry_locked()`, and `waitq_wake_nr_locked()`. Scheduler
  callbacks, spinlock wrappers, current-thread state transitions, wakeup
  wrappers, timers, and futex logic remain C-owned.
- Ported the small init/memory query helper cluster behind the existing C ABI:
  `find_command_line()` from `kernel/init.c`, plus
  `is_mckernel_memory()` and `phys_to_nid()` from `kernel/mem.c`. The page
  address validator, page-table/mapping code, and high-risk memory management
  behavior remain C-owned.
- Ported the page query/splitability helper cluster behind the existing C ABI:
  `page_to_phys()` and `is_splitable()` from `kernel/mem.c`. Page hash lookup,
  page-table walking, mapping/unmapping, and memory-object operations remain
  C-owned.
- Ported the exported bitops scan/hweight helper cluster behind the existing C
  ABI: `find_next_bit()`, `find_next_zero_bit()`, `find_first_bit()`,
  `find_first_zero_bit()`, and the `__sw_hweight*()` helpers.
- Ported the external string/memory leaf helper cluster behind the existing C
  ABI: `strlen()`, `strnlen()`, `strcpy()`, `strncpy()`, `strcmp()`,
  `strncmp()`, `strchr()`, `strrchr()`, `strpbrk()`, `strstr()`, `memcpy()`,
  `memcpy_long()`, `memset()`, and `memcmp()`. Left
  `flatten_strings_from_user()` in C because it depends on allocation and
  user-copy helpers.
- Ported the numeric parser leaf helper cluster behind the existing C ABI:
  `simple_strtoul()`, `simple_strtol()`, `simple_strtoull()`,
  `simple_strtoll()`, `strict_strtoul()`, `strict_strtol()`,
  `strict_strtoull()`, `strict_strtoll()`, and `strtol()`. Left varargs
  formatting and scanning in C.
- Ported selected bitmap primitives behind the existing C ABI.
- Ported bitmap hex/list parser helpers behind the existing C ABI:
  `__bitmap_parse()`, `bitmap_parse_user()`, `bitmap_parselist()`, and
  `bitmap_parselist_user()`. Left bitmap string/list printing in C because it
  depends on `scnprintf()`.
- Ported bitmap_find_next_zero_area() behind the existing C ABI.
- Ported the bitmap region helper cluster behind the existing C ABI:
  bitmap_find_free_region(), bitmap_allocate_region(), and
  bitmap_release_region().
- Ported the bitmap remap helper cluster behind the existing C ABI:
  bitmap_ord_to_pos(), bitmap_remap(), bitmap_bitremap(), bitmap_onto(),
  and bitmap_fold().
- Started the page allocator phase by porting the rbtree helper cluster
  `__page_alloc_rbtree_free_range()` and
  `__page_alloc_rbtree_alloc_pages()` behind the existing C ABI.
- Continued the page allocator phase by porting the generic bitmap-backed
  no-lock helper cluster behind C wrappers:
  `__ihk_pagealloc_large_nolock()`, `__ihk_pagealloc_alloc_nolock()`,
  `__ihk_pagealloc_reserve_nolock()`, `__ihk_pagealloc_free_nolock()`,
  `__ihk_pagealloc_count_nolock()`, and
  `__ihk_pagealloc_query_free_nolock()`. Public exported page allocator
  symbols and MCS lock/IRQ handling remain in C for now.
- Extended the page allocator Rust phase by porting the no-lock zero-free
  helper behind the exported C lock/log wrapper:
  `__ihk_pagealloc_zero_free_pages_nolock()`.
- Extended the rbtree allocator helper set with Rust-owned
  `__page_alloc_rbtree_reserve_pages()` and
  `__page_alloc_rbtree_get_root_chunk()`.
- Moved the NUMA add-free helper body to Rust behind the exported C logging
  wrapper: `__ihk_numa_add_free_pages()`.
- Moved the single-node NUMA deferred-zero helper to Rust behind the C
  all-node wrapper: `__ihk_numa_zero_free_pages_node()`.
- Moved the under-lock NUMA allocation body to Rust behind the exported C
  CPU-local-cache/lock/log wrapper: `__ihk_numa_alloc_pages_nolock()`.
- Moved the direct NUMA free-to-tree helper to Rust behind the exported C
  bounds/lock/log wrapper: `__ihk_numa_free_pages_to_tree_nolock()`.
- Moved the deferred NUMA free enqueue helper to Rust while keeping the
  exported C wrapper responsible for public orchestration and IKC/Linux zero
  requests: `__ihk_numa_defer_zero_free_pages()`.
- Moved NUMA free-path preflight and action selection to Rust:
  `__ihk_numa_free_pages_prepare()` now owns bounds checking, positive page
  filtering, zero-now clearing, and direct-vs-deferred action selection.
- Kept macro-heavy C headers in place so existing C call sites do not need a
  public include-style migration yet.
- Guarded selected C bitmap implementations so Rust can replace them without
  duplicate symbols.
- Guarded selected C page-allocator helper implementations so Rust can replace
  them without duplicate symbols while the C fallback build remains available.
- Guarded selected C string/memory leaf implementations so Rust can replace
  them without duplicate symbols while the C fallback build remains available.
- Guarded selected C priority-list implementations so Rust can replace them
  without duplicate symbols while the C fallback build remains available.
- Guarded selected C numeric parser and bitmap parser implementations so Rust
  can replace them without duplicate symbols while the C fallback build remains
  available.
- Guarded selected C waitqueue core implementations so Rust can replace them
  without duplicate symbols while the C fallback build remains available.
- Guarded selected C init/memory query helpers so Rust can replace them without
  duplicate symbols while the C fallback build remains available.
- Guarded selected C page query/splitability helpers so Rust can replace them

Public interface rules
------------------------------------------------------------

- Preserve syscall numbers.
- Preserve ioctl values.
- Preserve IKC packet formats.
- Preserve exported symbol names.
- Preserve public C headers during the migration.
- Use extern "C" for Rust functions replacing C implementations.
- Use #[repr(C)] for all shared ABI structs.
- Keep union-heavy and flexible-array-heavy interfaces pointer/raw-layout based
  until each call site is deliberately migrated.
- Do not make behavior-breaking ABI changes without a separate approved plan.

Controlled verification ladder
------------------------------------------------------------

Run the steps in order. Stop on the first failure. Do not proceed to runtime
checks until all earlier build and equivalence checks pass.

Success:

Stop condition:

- Keep future V11 repros bounded with `timeout`, preserve the full command log,
  and inspect recent McKernel kmsg before making broader subsystem changes.

V12: Phase-specific stress
--------------------------

Purpose:
- Keep future verification narrow and debuggable.

Rule:
- Each Rust port phase gets tests specific to the code just moved.

Examples:
- Allocator phase: allocation/free/coalescing stress before syscall tests.
- Page-table phase: mapping/unmapping/attribute tests before process tests.
- Futex phase: futex stress before file-object tests.

Success:
- The new Rust phase passes its specific stress tests, then passes V4 through
  V11.

Stop condition:
- If stress fails, do not port the next subsystem.

Phase 4: Page allocator

Operating rules for every phase
------------------------------------------------------------

- One subsystem moves at a time.
- Each phase must add or update its own narrow verification.
- C and Rust behavior must be proven equivalent before removing C code.
- Runtime smoke testing must happen before broad regression testing.
- If a verification step fails, stop at that step and log the exact failure in
  kernel.log.
- Keep the system bootable after every merge.
