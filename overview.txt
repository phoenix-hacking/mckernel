McKernel Rust Migration Overview
Updated: 2026-05-19

Overall Rust ownership estimate: 99% for the McKernel core helper/decision surface
Whole-tree Rust ownership estimate: 43% in overview2.txt

How to read this number
------------------------------------------------------------

This is a functional-area estimate, not a strict line-count. The Rust build
foundation and first shared primitives are in place, but most high-risk kernel
subsystems remain C. For the literal whole-McKernel target including IHK host
modules and user tools, use overview2.txt. A later tracking phase can add an
automated line-count and symbol ownership report.

Overall estimate: 99% Rust-owned for the McKernel core helper/decision surface.
Whole-tree ownership including IHK host modules and user tools is tracked in
overview2.txt and is currently estimated at 43% with arm64 deferred.

This percentage should be treated as a functional-area estimate, not a strict
line-count. A later phase can add an automated LOC counter.

Current completed Rust-owned behavior
------------------------------------------------------------

- Freestanding no_std Rust kernel crate exists under kernel/rust/.
- Rust can be linked into the x86_64 mckernel.img path.
- C fallback builds remain part of the migration contract.
- Rust exports C ABI replacements for the first rbtree, llist, and bitmap
  routines.
- Rust now owns the exported bit-scan and hweight helper cluster from
  `lib/bitops.c`: `find_next_bit()`, `find_next_zero_bit()`,
  `find_first_bit()`, `find_first_zero_bit()`, `__sw_hweight8()`,
  `__sw_hweight16()`, `__sw_hweight32()`, and `__sw_hweight64()`.
- Rust now owns the external string/memory leaf helper cluster from
  `lib/string.c` when ENABLE_RUST_KERNEL is on: `strlen()`, `strnlen()`,
  `strcpy()`, `strncpy()`, `strcmp()`, `strncmp()`, `strchr()`,
  `strrchr()`, `strpbrk()`, `strstr()`, `memcpy()`, `memcpy_long()`,
  `memset()`, and `memcmp()`. The allocation/user-copy dependent
  `flatten_strings_from_user()` body remains in C.
- Rust now owns the priority-list add/delete core from `kernel/plist.c`:
  `plist_add()` and `plist_del()`. This keeps futex queue ordering logic
  equivalent while leaving futex wakeup, locking, and scheduler side effects in
  C.
- Rust now owns the pure waitqueue list-manipulation core from
  `kernel/waitq.c`: `waitq_init()`, `waitq_add_entry_locked()`,
  `waitq_remove_entry_locked()`, and `waitq_wake_nr_locked()`. Scheduler
  callbacks, spinlock wrappers, current-thread state changes, wakeup wrappers,
  timers, and futex behavior remain C-owned.
- Rust now owns the small init/memory query helper cluster:
  `find_command_line()` from `kernel/init.c`, plus
  `is_mckernel_memory()` and `phys_to_nid()` from `kernel/mem.c`. The page
  address validator, page-table logic, mapping paths, and high-risk memory
  management behavior remain C-owned.
- Rust now owns the page query/splitability leaf helper cluster from
  `kernel/mem.c`: `page_to_phys()` and `is_splitable()`. The Rust side has
  direct `struct page` layout assertions, while page hash lookup, page-table
  walking, mapping, and memory-object operations remain C-owned.
