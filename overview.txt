McKernel Rust Migration Overview
Updated: 2026-05-18

Overall Rust ownership estimate: 12%

How to read this number
------------------------------------------------------------

This is a functional-area estimate, not a strict line-count. The Rust build
foundation and first shared primitives are in place, but most high-risk kernel
subsystems remain C. A later tracking phase can add an automated line-count and
symbol ownership report.

Current completed Rust-owned behavior
------------------------------------------------------------

- Freestanding no_std Rust kernel crate exists under kernel/rust/.
- Rust can be linked into the x86_64 mckernel.img path.
- C fallback builds remain part of the migration contract.
- Rust exports C ABI replacements for the first rbtree, llist, and bitmap
  routines.
- Rust now owns the exported bit-scan and hweight helper cluster from
  `lib/bitops.c`: `find_next_bit()`, `find_next_zero_bit()`,
  `find_first_bit()`, `find_first_zero_bit()`, `__sw_hweight8()`,
  `__sw_hweight16()`, `__sw_hweight32()`, and `__sw_hweight64()`.
- Rust now owns the external string/memory leaf helper cluster from
  `lib/string.c` when ENABLE_RUST_KERNEL is on: `strlen()`, `strnlen()`,
  `strcpy()`, `strncpy()`, `strcmp()`, `strncmp()`, `strchr()`,
  `strrchr()`, `strpbrk()`, `strstr()`, `memcpy()`, `memcpy_long()`,
  `memset()`, and `memcmp()`. The allocation/user-copy dependent
  `flatten_strings_from_user()` body remains in C.
- Rust now owns the priority-list add/delete core from `kernel/plist.c`:
  `plist_add()` and `plist_del()`. This keeps futex queue ordering logic
  equivalent while leaving futex wakeup, locking, and scheduler side effects in
  C.
- Rust now owns the pure waitqueue list-manipulation core from
  `kernel/waitq.c`: `waitq_init()`, `waitq_add_entry_locked()`,
  `waitq_remove_entry_locked()`, and `waitq_wake_nr_locked()`. Scheduler
  callbacks, spinlock wrappers, current-thread state changes, wakeup wrappers,
  timers, and futex behavior remain C-owned.
- Rust now owns the small init/memory query helper cluster:
  `find_command_line()` from `kernel/init.c`, plus
  `is_mckernel_memory()` and `phys_to_nid()` from `kernel/mem.c`. The page
  address validator, page-table logic, mapping paths, and high-risk memory
  management behavior remain C-owned.
- Rust now owns the page query/splitability leaf helper cluster from
  `kernel/mem.c`: `page_to_phys()` and `is_splitable()`. The Rust side has
  direct `struct page` layout assertions, while page hash lookup, page-table
  walking, mapping, and memory-object operations remain C-owned.
- Rust now owns the numeric parser leaf helpers from `lib/vsprintf.c`:
  `simple_strtoul()`, `simple_strtol()`, `simple_strtoull()`,
  `simple_strtoll()`, `strict_strtoul()`, `strict_strtol()`,
  `strict_strtoull()`, `strict_strtoll()`, and `strtol()`. Varargs
  formatting and scanning remain in C.
- Rust now owns bitmap hex/list parser helpers from `lib/bitmap.c`:
  `__bitmap_parse()`, `bitmap_parse_user()`, `bitmap_parselist()`, and
  `bitmap_parselist_user()`. Bitmap string/list printing stays in C because it
  depends on `scnprintf()` formatting.
- Rust now owns bitmap_find_next_zero_area(), bitmap_find_free_region(),
  bitmap_allocate_region(), and bitmap_release_region() when
  ENABLE_RUST_KERNEL is on, while the C implementations remain available for
  fallback builds.
- Rust now owns the first page-allocator rbtree helper cluster
  `__page_alloc_rbtree_free_range()` and
  `__page_alloc_rbtree_alloc_pages()` when ENABLE_RUST_KERNEL is on, while the
  C helper implementations remain available for fallback builds.
- Rust now owns the generic bitmap-backed page allocator no-lock helper
  cluster when ENABLE_RUST_KERNEL is on:
  `__ihk_pagealloc_large_nolock()`, `__ihk_pagealloc_alloc_nolock()`,
  `__ihk_pagealloc_reserve_nolock()`, `__ihk_pagealloc_free_nolock()`,
  `__ihk_pagealloc_count_nolock()`, and
  `__ihk_pagealloc_query_free_nolock()`. The exported C page allocator API and
  MCS lock/IRQ handling remain in C wrappers, and C fallback builds still use
  the original C implementation.
- Rust now owns the no-lock zero-free helper
  `__ihk_pagealloc_zero_free_pages_nolock()` behind the C exported
  `__ihk_pagealloc_zero_free_pages()` lock/log wrapper.
- Rust now owns the rbtree reserve/get-root helper pair:
  `__page_alloc_rbtree_reserve_pages()` and
  `__page_alloc_rbtree_get_root_chunk()`.
- Rust now owns the `__ihk_numa_add_free_pages()` helper body behind the
  exported C logging wrapper, including incoming range zeroing, rbtree
  insertion, min/max tracking, and free-page accounting.
- Rust now owns the single-node deferred-zero helper
  `__ihk_numa_zero_free_pages_node()` while the C wrapper still owns the
  all-node traversal and zero-at-free policy check.
- Rust now owns the under-lock NUMA allocation body
  `__ihk_numa_alloc_pages_nolock()` while the exported C
  `ihk_numa_alloc_pages()` wrapper still owns the CPU-local-cache precheck,
  MCS lock/unlock, and debug logging.
- Rust now owns the direct NUMA free-to-tree helper
  `__ihk_numa_free_pages_to_tree_nolock()` while the C wrapper still owns
  bounds checks, zero-now policy, locking, and logging.
- Rust now owns the deferred NUMA free enqueue helper
  `__ihk_numa_defer_zero_free_pages()` while the C wrapper still owns the
  public free orchestration and IKC/Linux zero request path.
- Rust now owns the NUMA free-path preflight helper
  `__ihk_numa_free_pages_prepare()`, including node bounds checks, positive
  page-count filtering, zero-now clearing, and direct-vs-deferred action
  selection. The C wrapper still owns locks, logging, CPU-local-cache handling,
  and the IKC/Linux zero request.
- Initial ABI/layout checks exist for shared structures.
- Primitive and allocator-helper equivalence testing exists in
  kernel/rust/tests/run_equivalence.sh.

Recommended verification style
------------------------------------------------------------

Run the ladder from plan.txt in order:

V0: Documentation integrity
V1: Source inventory
V2: Rust object only
V3: Rust primitive equivalence
V4: Rust-enabled kernel image
V5: C fallback kernel image
V6: User-space tools
V7: Host modules compile
V8: Module load only
V9: McKernel boot only
V10: Minimal user workloads
V11: Focused regression tests
V12: Phase-specific stress

Stop on the first failing step. Record the failing command, environment, and
error summary in kernel.log before making more changes.

Next migration target
------------------------------------------------------------

Recommended next code phase:
- Continue Phase 4 page allocator only after widening allocator stress, or take
  another bounded helper cluster if it has direct equivalence coverage and does
  not pull allocator/user-copy dependencies into Rust. Good candidates are
  non-varargs formatting helpers, simple list helpers, small exported
  arithmetic/utility functions, or the next memory helper only after its
  C/Rust harness can model the required page-address and page-table state.

Reason:
- The Rocky baseline is clean and the current Rust helper set has C/Rust
  equivalence plus image-build validation. The next allocator work should widen
  allocator-specific V12 stress around free/list movement and accounting before
  moving the remaining public `ihk_numa_free_pages()` lock/log/IKC
  orchestration. Keep IKC/Linux zero requests in C until deferred-free stress
  is broader.
