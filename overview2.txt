McKernel Whole-Tree Rust Completion Overview
Updated: 2026-05-22

Scope
------------------------------------------------------------

This file tracks the literal full McKernel Rust port target on Rocky Linux.
It is separate from overview.txt because overview.txt currently tracks the
McKernel core helper/decision surface, where some areas are much farther ahead
than the full source tree.

Target definition:

- Rocky Linux remains the paired Linux host target for the active x86_64 port.
- All McKernel-owned non-arm64 functional code is in scope for Rust ownership.
- IHK host modules remain tracked as full-tree context: ihk, ihk-smp-x86_64,
  and mcctrl. Active migration iterations should focus on McKernel-owned code
  unless the user explicitly asks to spend the iteration on IHK/external
  boundary work.
- User tools are in scope where they are McKernel-owned.
- Public C headers, ioctl numbers, syscall numbers, exported ABI symbols, and
  Linux-facing compatibility surfaces may remain as C ABI shims while logic
  moves to Rust.
- Architecture assembly, trampolines, context-switch assembly, and Linux
  kernel internals are not counted as Rust-port debt unless the project later
  chooses to replace them.
- arm64 is deferred and excluded from the active completion denominator until
  the x86_64/Rocky target is stable.

Mechanical Ownership Report
------------------------------------------------------------

The area estimates above remain functional estimates. A conservative LOC
denominator is now available:

`scripts/rust-ownership-report.py --top 25 --check-dashboard overview.txt --check-dashboard overview2.txt`

Current x86_64 active-scope baseline from that script:

- Rust implementation LOC: 18,501.
- C implementation-debt LOC: 98,475.
- C/header boundary LOC: 27,582.
- Required assembly LOC: 872.
- Tests/smokes LOC: 117,863.
- External/generated LOC: 230,989.
- Mechanical Rust implementation share: 15.8%.

This mechanical number is intentionally lower than the functional estimate
because it treats mixed C wrapper files as C implementation debt until the file
is reduced to an explicitly allowed boundary. External/vendor code is reported
for visibility but excluded from the Rust ownership denominator.

What Counts As 100%
------------------------------------------------------------

An area is not complete until the Rust path is the primary implementation and
the matching C path is either removed, retained only as a compatibility shim,
or documented as a deliberate external boundary.

The full-tree target reaches 100% only when all non-arm64 areas above are
Rust-owned and these gates pass:

- Rust-enabled full McKernel image builds on Rocky.
- C fallback image still builds until the fallback is intentionally retired.
- IHK Linux host modules build and load with Rust-owned logic behind their
  Linux-facing entry points.
- User tools build from Rust or are reduced to thin compatibility wrappers.
- McKernel boots on Rocky with McKernel cores.
- Non-root mcexec smoke passes.
- procfs/sysfs smoke passes.
- SysV shared memory smoke passes.
- XPMEM runtime smoke passes when /dev/xpmem is present.
- Memory-management smoke covers mmap, brk, mprotect, munmap, mincore,
  page-fault, file-backed mmap, and hugetlbfs-backed mappings.
- Scheduler/futex smoke covers wait, wake, timeout, requeue, affinity, and
  timer behavior.
- Regression tests include targeted equivalence tests for every moved helper
  plus runtime probes for every moved mutation-heavy path.

Current Blockers To 100%
------------------------------------------------------------

- Rust build/link and module-load smoke now pass for `ihk`, `ihk-smp-x86_64`,
  and `mcctrl`; a focused IHK module helper smoke covers page-allocator bitmap
  mutation, mcctrl sysfs mapping helpers, and Tofu device-name buffer fill, but
  refcount mutation, lock/list mutation, broad allocation/lifetime ownership,
  memory registration, and IKC exchange remain pending.
- Most user tools still use C orchestration, even though `mcstat`, `mcexec`,
  `ihklib`, `ihkconfig`, `ihkosctl`, `ihkmond`, `mcinspect`, `eclair`, and the
  crash extension now link Rust helper objects for substantial parsing,
  formatting, policy, and output-decision slices.
- x86_64 page-table and TLB-sensitive mutation are still C because direct
  runtime probes must exist before moving them.
- Process lifetime and VM range mutation are still C because child-list,
  reparenting, rusage, locking, and teardown paths need staged runtime tests.
- Syscall dispatch and user-copy-heavy handlers are still C.
- Futex queue/wake internals, timer mutation, and scheduler callbacks are
  still C.
- Direct XPMEM runtime remains host-dependent; use /dev/xpmem when present and
  keep helper-only conversions until runtime coverage exists.
